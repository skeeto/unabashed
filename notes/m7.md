## Principles

1. bash 5.3 is the reference, as always: recorded specs (t/exec,
   t/posix), its own test suite in the oracle container, and Git Bash
   for msys behaviour.
2. The pass list is a manifest (t/oracle-posix.txt): for every run-*
   test, PASS (only warnings), BASH (fails exactly as bash 5.3 does in
   the same container: the environment's doing) or FAIL. A test never
   moves down; the exit criterion freezes the list with categories d
   (jobs, trap, coproc, errors, read) and e (intl, nquote4, printf,
   glob-test) at PASS or BASH.
3. Help text is our own. Usage synopses (`cd [-L|[-P [-e]]] [-@]
   [dir]`) are interface facts the messages already print; the
   descriptions are written fresh, never copied from bash's
   builtins/*.def or its documentation (GPL).
4. Testing rules stay: randomized tests only on the vos; real
   processes, terminals and signals only in the oracle container, the
   sandbox, or curated scripts on Windows and XP.


## Steps

Waves: 1; then 2 to 6 in any order; 7 after 2; 8 after 7; 9 after
the rest; then 10.

1. **Oracle manifest.** tools/oracle-posix runs a failing test again
   under bash 5.3 and calls it BASH when the outputs are identical;
   `-v` diffs ours against bash's; `-m MANIFEST` reports regressions.
   Commit the first t/oracle-posix.txt.
2. **Remaining builtins.** `ulimit` (an `os_rlimit` in the platform
   API: getrlimit/setrlimit on POSIX, a modelled table on the vos, the

   modify limit"), `pushd`/`popd`/`dirs` (the dirstack test), `enable`

3. **help.** `help`, `help -d -m -s`, patterns, and every builtin's
   `--help`: synopses as bash prints them, descriptions our own.
4. **Invocation.** Long options (`--help`, `--version`, `--verbose`,
   `--dump-strings`, ...), option errors and the usage text, the
   order rules (long options after short ones), "bad interpreter",
   the remaining startup gaps of issues.md, exportfunc's import rules
   (names that are not identifiers, `export` refusing them).
5. **Restricted shell.** `-r`, `rbash`, `set -r`: cd, PATH, SHELL,
   ENV, BASH_ENV, redirections, `/` in command names, `exec`,
   `enable`, `command -p` (the rsh test).
6. **POSIX mode.** posixexp's field splitting of `${x-$y}` and `$'...'`
   in parameter names, source_searches_cwd, and the posix-mode rows
   of issues.md; posix2 and posixexp* green.
7. **Job control on POSIX.** Process groups and the terminal: the
   shell in its own group, each job in one, tcsetpgrp around
   foreground jobs, SIGTSTP/SIGTTIN/SIGTTOU handling; `set -m` in

   `suspend`, `kill -STOP/-CONT`, `wait` on a stopped job, "There are

   parts of a foreground job run on fibers: the job's processes share
   a group, and Ctrl-Z stops what can be stopped (design first, in
   this file). The jobs and errors tests.
8. **Job control on Windows.** `fg` and `bg` of running jobs, `jobs`
   states, `wait`, `kill`; Ctrl-Z stays out (plan.md). The Win32

9. **Fidelity sweep.** The M7 issues not covered above: traps (CHLD,
   WINCH), nameref scopes, dollars, redir line numbers, read -t,

10. **Closing.** The manifest frozen (categories d and e at PASS or

## Implementation


### Step 1: the oracle manifest

- tools/oracle-posix runs each failing test a second time with the
  image's bash 5.3 as THIS_SH and compares the two outputs byte for
  byte: equal is BASH (this container fails it for bash too), else
  FAIL, with `-v` showing ours as a diff against bash's (more telling
  than against the .right file, which the environment already
  disturbs). `-m MANIFEST` reads "NAME RESULT" lines and fails on a
  test that does worse (PASS > BASH > FAIL), noting ones that do
  better.
- First manifest, t/oracle-posix.txt (after 3add727): 62 PASS, 4 BASH
  (glob-bracket, heredoc, read, test), 20 FAIL: builtins, complete,
  dirstack, dollars, errors, execscript, exportfunc, glob-test,
  history, intl, invocation, jobs, nameref, posixexp, printf,
  procsub, redir, rsh, trap, vredir.
