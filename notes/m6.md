## Where the code stood at the start (9f9dc77)

- An interactive shell (`-i`, or stdin and stderr terminals) reads its
  input with `fillstdin` (unabashed.cpp): the prompt (`${PS1@P}`,
  `${PS2@P}`) written to fd 2, then the line one byte at a time from
  fd 0, the terminal in its cooked mode (the console's line input on
  Windows). Ctrl-C at the prompt discards the line (status 130).
- No terminal API beyond `os_isatty`. The vos has `ttyin`: fd 0 is a
  terminal that never delivers input.
- No history list, no `history` or `fc` builtin, no history expansion;
  `set -o history`/`-H` are accepted and do nothing. HISTCMD reads 1 or
  0. `\!` and `\#` in prompts expand to fixed numbers.
- `compgen` handles -abekv, -A, -W, -P, -S, -X; no `complete`,
  `compopt`, or completion engine. `read -e/-p/-s/-i` do nothing.
- PROMPT_COMMAND, PS0: check at step 2.


## Principles

1. One editor core, emitting a fixed VT subset (CR, cursor moves,
   erase to end of line and screen, SGR reverse, bracketed paste
   on/off) and reading xterm key bytes. Platforms only move bytes, set
   the terminal's mode and report its size; nothing about editing is
   per platform. A legacy Windows console (XP, 7, or VT mode refused)
   gets the same bytes, interpreted by `vtcon.cpp` in the core over a
   few console primitives, and its key events become xterm bytes in the
   core too, so the vos's Windows personality tests both.
2. Everything is testable on the vos: a virtual terminal (`vterm.cpp`,
   a screen of cells with or without deferred wrap) behind fd 0/1/2,
   scripted keys, virtual time for the key sequence timeout, screen
   goldens. Randomized tests (the editor fuzzer) only there.
3. bash 5.3 with its readline is the reference, through the screen:
   what the terminal shows (text, cursor position) after each key must
   match, not the escape sequences that drew it. Recorded with
   `tools/ptyrun` in the oracle container (a pty, keys fed with pauses,
   both outputs rendered by the same vterm), as tools/record does for
   specs. Only our scripts and the rendered screens are committed.
4. The non-interactive paths stay as they are: the editor runs only for
   an interactive shell reading a terminal, and for `read -e`.
5. readline's source is a reference for behavior only (GPL): the
   research notes and observed screens, never its code.


## Steps

Waves: 1; then 2; then 3, 4, 5 and 6 in any order; 7 and 8 after 2;
then 9; then 10.

1. **Terminal API and the vos terminal.** `os_ttyopen`/`os_ttymode`
   (raw, restored), terminal size and resize events, terminal reads
   with a deadline (key sequence timeout). `vterm.cpp`: the VT subset
   parsed into a cell screen (UTF-8, wide characters, deferred wrap on
   or off, scroll), used by the vos as the terminal behind fd 0/1/2
   and by tools. Test format `t/edit/*.sh`: setup, keys (with pauses),
   expected screen and cursor at marked points.
2. **Editor core** (`edit.cpp`). Line buffer (UTF-8), redisplay from a
   screen model with diffs (wrapping with and without xenl, `^X` and
   `M-x` forms, tabs, wide characters, prompts with `\[ \]` and their
   miscounting, multi-line prompts), the P0 keys (self-insert, motion,
   delete, C-a/e/f/b/d/h/k/u/w/l, arrows, Home/End, accept, C-c, C-d
   with IGNOREEOF), PROMPT_COMMAND, PS0, LINES/COLUMNS (checkwinsize),
   TERM=dumb fallback. `fillstdin` uses it. `read -e/-p/-s/-i/-t` on a
   terminal. The Ctrl-C-ignored-on-entry item (issues.md).
3. **History.** The list (HISTSIZE, HISTCONTROL, HISTIGNORE, cmdhist,
   lithist, timestamps), HISTFILE read at startup and written at exit
   (HISTFILESIZE, histappend, HISTTIMEFORMAT lines), `history` (every
   option), `fc` (-l, -s, editor runs), HISTCMD, `\!`/`\#`; history
   expansion (`!` events, word designators, modifiers, `^a^b`,
   histverify, histreedit, `:p`, histchars); `set -o history`/`-H`.
   bash's history and histexpand tests on the vos.
4. **The emacs keymap.** Numeric arguments, words (readline's and
   shell-*), case, transpose, kill ring with append, yank, yank-pop,
   undo (merged inserts, groups, per-history-line lists), revert-line,
   previous/next history, M-< M->, M-. and M-C-y, C-o, quoted-insert,
   isearch (C-r/C-s, terminators, C-w/C-y, C-g), M-p/M-n,
   history-search-*, the C-x map, insert-comment,
   shell-expand-line, history-expand-line, edit-and-execute-command,
   bracketed paste, the key sequence timeout, bell-style.
5. **Completion.** Word breaks (COMP_WORDBREAKS), bash's default order
   (variables, `$(`, `~user`, `@host`, command position, files),
   quoting and dequoting of the word, the appended character, FIGNORE,
   mark-directories; listing in columns, `Display all N
   possibilities?`, `--More--`; M-? M-* M-/ M-! M-$ M-~ M-@ and their
   C-x forms, menu-complete; completion-ignore-case and map-case,
   show-all-if-ambiguous/unmodified; Windows: `.exe` and PATHEXT,
   completion_strip_exe (issues.md). Programmable completion stays in
   M8 (plan).
6. **inputrc basics.** `$INPUTRC`, `~/.inputrc`, `/etc/inputrc` (msys
   mode: the install's), `set` with the variables of readline.md §5
   that steps 2-5 implement, `keyname:` and `"keyseq":` bindings to
   functions, `$include`, C-x C-r. `$if`/`$else`/`$endif` with mode,
   term, Bash and version tests are parsed and evaluated here (Git for
   Windows' /etc/inputrc relies on them); macros and `bind` stay in M8.
7. **POSIX terminal.** termios raw mode, restored around every
   foreground program and at exit, SIGWINCH, the size. `tools/ptyrun`
   in the oracle container: bash and ours on a pty, the same keys, the
   screens compared after each step; a corpus of recorded sessions.
8. **Win32 console.** VT mode (ENABLE_VIRTUAL_TERMINAL_PROCESSING,
   DISABLE_NEWLINE_AUTO_RETURN for deferred wrap) where the console
   takes it; key events from ReadConsoleInputW to xterm bytes (arrows,
   Home/End/Delete/Insert/PgUp/PgDn with modifiers, Alt as ESC, AltGr
   as text, VK_PACKET, surrogate pairs, Ctrl-C as a key while editing);
   WINDOW_BUFFER_SIZE_EVENT; console modes saved and restored around
   every foreground program; `vtcon.cpp` for the legacy console, the
   vos modelling one in its Windows personality; mintty and other
   pipe "terminals" stay cooked (plan: low priority).
9. **Editor fuzzer.** `FUZZ_EDIT`: random key bytes into the vos
   terminal. Properties: no trap; after each key the terminal's screen
   equals a full redraw of the editor's state from scratch (diff
   redisplay agrees with its model); the same with deferred wrap off
   and on, and through vtcon.
10. **Closing.** winctl end to end on Win11 conhost, Windows Terminal
    and the XP laptop; ptyrun corpus green; exit criteria; issues.md.


## Decisions

- Screens, not bytes: our redisplay may draw differently from
  readline's as long as every intermediate screen and cursor position
  match (principle 3). Bells are compared as events.
- inputrc conditionals come forward from M8 (step 6): a real inputrc
  cannot be read correctly without them.
