## Where the code stood at the start (9f9dc77)

- An interactive shell (`-i`, or stdin and stderr terminals) reads its
  input with `fillstdin` (unabashed.cpp): the prompt (`${PS1@P}`,
  `${PS2@P}`) written to fd 2, then the line one byte at a time from
  fd 0, the terminal in its cooked mode (the console's line input on
  Windows). Ctrl-C at the prompt discards the line (status 130).
- No terminal API beyond `os_isatty`. The vos has `ttyin`: fd 0 is a
  terminal that never delivers input.
- No history list, no `history` or `fc` builtin, no history expansion;
  `set -o history`/`-H` are accepted and do nothing. HISTCMD reads 1 or
  0. `\!` and `\#` in prompts expand to fixed numbers.
- `compgen` handles -abekv, -A, -W, -P, -S, -X; no `complete`,
  `compopt`, or completion engine. `read -e/-p/-s/-i` do nothing.
- PROMPT_COMMAND, PS0: check at step 2.


## Principles

1. One editor core, emitting a fixed VT subset (CR, cursor moves,
   erase to end of line and screen, SGR reverse, bracketed paste
   on/off) and reading xterm key bytes. Platforms only move bytes, set
   the terminal's mode and report its size; nothing about editing is
   per platform. A legacy Windows console (XP, 7, or VT mode refused)
   gets the same bytes, interpreted by `vtcon.cpp` in the core over a
   few console primitives, and its key events become xterm bytes in the
   core too, so the vos's Windows personality tests both.
2. Everything is testable on the vos: a virtual terminal (`vterm.cpp`,
   a screen of cells with or without deferred wrap) behind fd 0/1/2,
   scripted keys, virtual time for the key sequence timeout, screen
   goldens. Randomized tests (the editor fuzzer) only there.
3. bash 5.3 with its readline is the reference, through the screen:
   what the terminal shows (text, cursor position) after each key must
   match, not the escape sequences that drew it. Recorded with
   `tools/ptyrun` in the oracle container (a pty, keys fed with pauses,
   both outputs rendered by the same vterm), as tools/record does for
   specs. Only our scripts and the rendered screens are committed.
4. The non-interactive paths stay as they are: the editor runs only for
   an interactive shell reading a terminal, and for `read -e`.
5. readline's source is a reference for behavior only (GPL): the
   research notes and observed screens, never its code.

## Decisions

- Screens, not bytes: our redisplay may draw differently from
  readline's as long as every intermediate screen and cursor position
  match (principle 3). Bells are compared as events.
- inputrc conditionals come forward from M8 (step 6): a real inputrc
  cannot be read correctly without them.

## Implementation

### Step 1: the terminal API and the vos terminal

- `os_tty(in, out, how)` (api.cpp): TTY_QUERY, TTY_RAW (no echo, no
  canonical input, no signals from keys, no CR translation of input;
  Win32 also asks for VT input and output and deferred wrap), and
  TTY_RESTORE; it reports the size, deferred wrap (`xenl`), a legacy
  console, and the special characters. POSIX: termios and TIOCGWINSZ.
  Win32: console modes and the screen buffer's width and window height.
- `unicode.cpp` (core): `cpwidth`, a table of the 498 ranges whose
  width is not 1, generated from glibc 2.41's wcwidth under C.UTF-8
  (unassigned code points as 1, as terminals draw them).
- `vterm.cpp` (tests and tools): the screen model (cells, UTF-8, wide
  and combining characters, deferred wrap on or off, insert mode, the
  CSI subset readline's xterm entry uses, OSC skipped) and `vtdump`;
  also the `.ed` script format and its parser.
- The vos's terminal (`VTty`): descriptors 0-2 and /dev/tty draw on a
  VTerm (\n as \r\n) and read the script's keys; a cooked mode with
  echo, erase, kill, werase, ^C (a group signal: `os_siggroup` is now
  real in the vos) and ^D; snapshots once every other process waits;
  pauses in virtual time; resizes with SIGWINCH.
- `tools/ptyrun` and `tools/edrecord` record bash's screens in the
  oracle container (tools/README.md).
- Found on the way: an interactive shell's `exit` prints `exit` (or
  `logout`) to stderr, as bash's does; ours printed nothing.

### Step 2: the editor core

- `edit.cpp`: one editor per process (its own arenas), a key trie of
  bindings to EF_* functions, the line as UTF-8 bytes. Redisplay lays
  the prompt and line out into rows of cells (wide characters moved
  whole to the next row, `^X` for controls, tabs to 8, deferred wrap
  or not) and diffs that layout against the one on screen, row by row.
  Motion by characters keeps a combining mark with its base, as
  readline does; self-insert takes a UTF-8 sequence whole.
- `fillstdin` uses it when interactive with emacs or vi set (an
  interactive shell sets emacs unless `--noediting`); the prompt's
  `\1 \2` markers delimit invisible text. Ctrl-C echoes `^C` at the
  cursor, then a newline; the line is dropped with status 130.
- At an end of input at the start of a command, an interactive shell
  prints `exit` (`logout` in a login shell), with or without the
  editor, as bash does; IGNOREEOF asks for `exit` instead, as many
  times as its value (atoi, 10 if empty).
- The oracle image now links bash against libtinfo: with its bundled
  termcap and no /etc/termcap, readline drew as on a dumb terminal.
- PROMPT_COMMAND (a string, or each element of an indexed array) runs
  before each primary prompt; `$?` and `$_` survive it. PS0 is shown
  after a command is read, before it runs.
- LINES and COLUMNS: plain shell variables, set when the size the
  editor sees changes (at its start and end, and on a resize).
- A resize while editing (SIGWINCH; the vos's `resize`): as readline,
  the rows of the line are cleared from the bottom up and the line
  drawn again for the new width. The editor's read takes any signal
  (Task.anysig: never the scheduler's direct blocking read), and
  fileread returns -4 to it. POSIX catches SIGWINCH while the terminal
  is raw, if nothing else handles it.
- A line that fills its last row exactly has an empty row after it
  wherever the cursor is, and a space written there makes the terminal
  wrap, as readline does (the screens differ otherwise).
- The editor hangs off Shell (shared by subshells, dropped from
  images) instead of a static: the test runner runs many vos shells
  in one process.
- `read` on a terminal: `-p` (to stderr), `-s`, `-n`/`-d` in the
  terminal's byte mode (os_tty TTY_NOECHO, TTY_CHARS, TTY_CHARSNOECHO;
  restored on any way out), PS2 after a backslash-newline in an
  interactive shell. `-e` reads with the editor (EdRead: `-i` text,
  `-n` accepts at that many characters, `-d` byte accepts and CR
  inserts, `-s` shows only the prompt); Ctrl-C there clears the line,
  echoes `^C` and acts as SIGINT; Ctrl-D gives status 1. All are off
  when the input is not a terminal.
- A line that exactly fills its rows, accepted with the cursor alone
  on the empty row after them, gets no further newline (readline's
  `_rl_update_final`).
- An interactive shell (and the `-i` it implies with no `-c` or
  script when stdin and stderr are terminals) catches SIGINT, SIGQUIT
  and SIGTERM as bash does, even when they were ignored on entry
  (SIGM_CLAIM; Win32 clears the inherited Ctrl-C ignore); `trap`'s
  ignored-on-entry rule and the programs it runs still see them as
  ignored (Shell.entryign). Ctrl-C during a command writes the newline
  after the echoed `^C` before the next prompt.
- The vos terminal types ahead as a real one does: while nothing reads
  it (a busy command), keys go through its cooked line discipline once
  the screen has been quiet 300 ms, as tools/ptyrun waits; a busy
  shell's polls pass time, take snapshots, and kill it (9) when the
  keys run out. A zero-length read of the terminal asks only whether
  typed bytes wait (vttyhas), never takes a snapshot.
- Self-insert takes the typed keys already waiting that insert
  themselves in one go, then shows the line once, as readline batches
  typeahead (not under `read -n`); a key read ahead is put back.
- TERM=dumb, or one row: the line stays on one row, scrolled sideways
  as readline does (its margin rule: the cursor two thirds across once
  it would leave the screen, `<` and `>` where the line goes on), drawn
  with CR and plain text only.
- t/edit 001-013: echo, motion, kill, wrap with and without deferred
  wrap, exact-width lines, wide and combining characters, multi-line
  and invisible prompts, control characters, Ctrl-C and Ctrl-D, clear,
  PROMPT_COMMAND and PS0, LINES/COLUMNS, resize; 014-015, read; 016,
  Ctrl-C during a command and keys typed meanwhile; 017, TERM=dumb. All also pass with
  the POSIX build on a pty in the oracle container
  (`EDRECORD_SHELL=tools/unabashed-linux EDRECORD_CHECK=1`).

### Step 3: history

Semantics: notes/research/history.md (a digest of bash's bashhist.c,
readline's history files and expansion, and the history and fc
builtins, with the oracle checks done on Git Bash and bash 5.3).

- `history.cpp`. The list is a Hist in the Shell by value, its entries
  immutable HistEnt in the store; the entry array is copied before a
  subshell changes one its parent owns (histown), so a synchronous
  subshell's history rolls back with it, and copyhist deep-copies it
  for vprocs and images. HISTSIZE stifles as readline does (shrinking
  renumbers from the count dropped); HISTCONTROL, HISTIGNORE (with `&`
  and ignoredups' memory), erasedups.
- Lines reach it through a hook on the parser's line reader
  (Lexer.hist, set by runsource for the reader and, after
  `set -o history`, for `-c`): each physical line and each
  here-document line. cmdhist joins a multi-line command into its first
  entry with bash's delimiter rules (history_delimiting_chars: `;`,
  none, or a newline, by the tokens and the open delimiters); lithist
  keeps newlines. HISTCMD, `\!` and `\#` follow bash, including its
  pointer comparison for which prompt is expanding (PS4 counts as one).
- The history file: read whole at startup after the startup files (and
  on `set -o history` with nothing added yet), HISTFILESIZE cutting it
  first and on every assignment (HISTFILE, or `$HOME/.history`
  unset); readline's range read (time stamp lines, the multiline mode
  that never resets, an unterminated last line ignored, a failed open
  zeroing the lines-read count but a non-regular file not); writes
  in place (OF_TRUNC, 0600) or appended; time stamp lines written only
  while HISTTIMEFORMAT has been set (the hook's flag). A stamp is the
  comment character and the epoch seconds; with no comment character
  (a script that never set HISTTIMEFORMAT or `-H`) it starts with a NUL
  byte as readline's does, so it is never written and lists as a time
  only while the comment character stays NUL. The save at exit follows
  the EXIT trap: append this session's lines, or overwrite when HISTSIZE
  dropped some of them, then truncate.
- `history`: every option, bash's processing order, messages and
  statuses; `-d` offsets and ranges; `-s` and `-p` removing their own
  line; `-a -n -r -w` with the line counts readline keeps.
- Expansion: readline's two passes (the first only looks for a
  reference bash's veto lets through, judged on the line as read; the
  second expands and judges each `!` by the output so far, as readline
  hands the hook). The veto is bash's: `[!`, `${!`, `$!`, extglob
  `!(`, and its quote scanner, which hops from one unquoted `!` to the
  next, each hop starting outside quotes, with one level of `$(` and
  backquotes. Events, word designators (history_tokenize's words: fds
  with redirections, `$(...)` and extglob groups whole), modifiers
  including `s`/`&` with g/a/G, `:p` making the line print-only (still
  added), `^old^new^`, `!#`, `?str?` and `%`. The expanded line goes to
  stderr; a failed line is dropped with `$?` kept, and as in bash it is
  not counted: the message has the line number, and LINENO from then
  on runs one short per dropped line. On a continuation line the
  partial entry is hidden. `-c` strings and `fc` runs are not
  expanded; here-documents are not.
- `set -v` with history on echoes the lines as the hook left them
  (expanded; a dropped line not at all), collected by the lexer
  (Lexer.echo).
- histverify and histreedit preload the editor's next line
  (Hist.preload; EdRead.shell marks the shell's own line, not
  `read -e`).
- `fc`: list (`-lnr`, bash's last_hist and fc_gethnum rules), `-s` with
  pat=rep pairs (the `fc` line replaced by the command in history, run
  with history off), and the edit form: a `bash-fc-` file in TMPDIR (or
  /tmp) made with OF_EXCL, `${FCEDIT:-${EDITOR:-vi}}` (ed in posix
  mode) run with history off, then the file run with history on and
  verbose; `os_unlink` (new in the platform API; the vos had one for
  the fakes) removes it.
- `set -n`: ignored once interactive, as bash; a command-line `-n` with
  `-i` holds (and skips the job-control warning).
- The Makefile now lists history.cpp (builds were stale without it).
- t/exec 883-886 (recorded with bash 5.3): the list in a script, the
  file, expansion read from a script, fc. Bash's run-histexpand passes
  on the vos; run-history differs only in history4 (readline keys: C-r
  and C-o, step 4) and history7 (readline echoing input read from a
  non-terminal under `-i`; issues.md).

### Step 4: the emacs keymap

Semantics: notes/research/emacs.md (a digest of readline's emacs
keymap, bash's additions, and the oracle checks on bash 5.3).

- The keymap is readline's emacs map with bash's additions (edbindings),
  including the ESC-uppercase do-lowercase-version entries, ESC digits,
  the C-x map, PgUp/PgDn as history-search (termcap kP/kN on the
  oracle) and Insert as overwrite-mode. Names follow readline's funmap
  (edfuncs) for inputrc in step 6.
- Numeric arguments: digit-argument and universal-argument with
  readline's last-command rules, `(arg: N) ` shown before each key,
  M-- alone meaning -1, a limit of 1000000.
- Undo as readline's: insert, delete and group records; single-byte
  inserts merge up to 20 bytes; every history entry the editor changes
  keeps its own list and original text (HistEnt.orig, .undo; histedit),
  shown with `*` by `history` and reverted when another line is
  accepted. revert-line, and undo of a whole yank or expansion.
- The kill ring: ten entries, appending or prepending while kills
  follow each other; yank, yank-pop (only after a yank), the mark set
  by kills as readline's emacs mode does, kill-region,
  copy-region-as-kill, copy-*-word, and the region shown in standout
  for one command after it is made active (exchange-point-and-mark,
  yanks, searches, paste).
- Words: readline's (alphanumeric) and bash's shell-* words, which
  follow quoting (char_is_quoted's rules); case commands,
  transpose-chars/words, delete-horizontal-space, character search
  both ways, insert-comment (with an argument, toggles), overwrite
  mode.
- History: motion with the new line saved while away, M-< M->, C-o
  (operate-and-get-next, applied before the next line's first draw),
  yank-last-arg and yank-nth-arg on history_tokenize's words.
- Searches: incremental (C-r, C-s, a negative argument reverses them):
  readline's loop, C-w and C-y pulling from the line, C-g restoring,
  ESC ending after a 100 ms wait for a sequence, any other bound key
  ending the search and then running; non-incremental (M-p, M-n, an
  empty string reusing the last one); history-search-* (prefix up to
  point, duplicates skipped, point after the prefix, mark at the end).
- shell-expand-line (history expansion, then the word expansions with
  no brace or pathname expansion, under an escape guard so an error
  only fails the command) and history-expand-line, both with bash's
  point rules; an error or `:p` result is printed below the line and
  the line drawn again. magic-space.
- Bracketed paste: the editor turns the mode on for each line and off
  at its end (`\e[?2004h`, `\e[?2004l\r`, as readline) unless the
  terminal is a dumb or legacy one; a paste is inserted whole, CR as
  LF, as one undo group, and left as the active region. A newline in
  the line starts a new row in the layout.
- The first draw of a line starts at the cursor, as readline, so a
  prompt follows output that has no final newline. The prompt is
  copied into the editor's memory: shell-expand-line reuses the
  caller's scratch.
- A line dropped by history expansion (histverify, or an error under
  histreedit) that was the first of a command is followed by PS1, not
  PS2.
- t/edit 018-027 (recorded with bash 5.3). Two artifacts of typing
  every key at once, avoided in the scripts: C-s is the terminal's
  XOFF on the oracle's pty, and a C-@ right after typed text is lost in
  bash (readline's typeahead pushback takes the NUL for no key).
- run-history's history4 types keys into `-i` reading from a pipe, so
  it waits on the non-terminal item, with history7.

### Step 5: completion

Semantics: notes/research/completion.md (readline's engine and bash's
classifier, generators, quoting and listing, with the oracle checks).

- `complete.cpp`, after edit.cpp. One attempt: find the word (the
  forward quote scan over the whole line before point, then the
  backward scan for COMP_WORDBREAKS, skipping quoted breaks only when
  the line has quoting), generate, sort (byte order, as the oracle's
  C.UTF-8) and drop duplicates, filter (FIGNORE with force_fignore,
  directories only, everything), take the common prefix (case folded
  with completion-ignore-case, spelled as the first match agreeing with
  the typed case), then act on the mode.
- Modes as readline's: TAB, list (`?`, with the single-match case after
  a failed attempt), insert all (M-*), show-all-if-ambiguous and
  -unmodified. TAB lists only when the last command was the same
  completion command and it changed nothing, so a TAB that inserted a
  prefix makes the next TAB a plain one.
- bash's classifier: command position from the one character before
  the word (`;|&{(` and backquote, with the `>&`, `>|`, `${` and
  extglob exceptions; reserved words do not count), or the word after
  only assignments; `$` and `${` variables (a single match naming a
  directory gets `/`), backquoted command words, `@` hosts from
  HOSTFILE or /etc/hosts, command words (aliases, reserved words,
  functions, builtins, the word itself if a directory, PATH
  executables; directories only when nothing matched; no_empty_cmd_
  completion), glob patterns (several matches dropped in TAB mode),
  file names. `read -e` completes file names only.
- File names: the directory as typed is kept in the result, opened
  after tilde expansion and, for `$` words that do not exist as named,
  parameter expansion (never a command substitution); direxpand puts
  the expansion into the line. `.` and `..` match a non-empty prefix;
  match-hidden-files hides dot files from an empty one; map-case.
- Quoting: whether at all (a quote-set character in the match, or any
  quoting before point), then the style (backslashes; the open quote
  continued, closed for a single match; double quotes for a `$` name
  that does not exist literally, leaving `$` alone; single quotes for a
  newline; history's `!` turning an open double quote into backslashes
  and dropping the quote). The specific commands quote without bash's
  full quoting. The append character: `/` for a directory even mid-line
  and nothing else, nothing for a link to a directory on the first TAB,
  otherwise the closing quote and space only at the end of the line.
  The replacement is one undo group, each appended piece its own.
- The listing: below the line's last row, printable parts (after the
  last slash), `/` marks or visible-stats, columns down (or across),
  completion-prefix-display-length, `Display all N possibilities? (y
  or n)`, the `--More--` pager, then the whole prompt (its earlier
  lines too) and the line drawn afresh below. C-g at either question
  rings and redraws (bash leaves a garbled display).
- Commands: complete, possible-completions (M-? M-=), insert-completions,
  complete-filename and the C-x / list, complete-command (M-!, C-x !),
  complete-variable (M-$, C-x $), complete-hostname (M-@, C-x @),
  complete-username (M-~, C-x ~: no user database, so nothing),
  dynamic-complete-history (M-TAB), glob-complete-word (M-g),
  menu-complete and menu-complete-backward (unbound),
  delete-char-or-list.
- The readline variables completion reads live in the editor (EdVars)
  with readline's defaults, for inputrc to set in step 6.
- t/edit 028-034 (recorded with bash 5.3): TAB and lists, command
  words, quoting, the pager and the question, variables and the
  specific commands, marks and links and FIGNORE, the redraw below a
  two-line prompt and a wrapped line. An empty line's command list
  differs from the oracle's only by builtins not yet written (dirs,
  pushd, popd, enable, help, bind, complete, compopt, ulimit) and the
  container's own programs, so no script lists it.

### Step 6: inputrc

inputrc.cpp reads readline's init file (notes/research/inputrc.md, a
digest of readline's behaviour in our own words, with the scenarios it
proposed).

- When: the editor's first use, so the rc file runs first and the
  messages come before the first prompt. Which: the last file read,
  else INPUTRC (the shell variable, final even if missing), else
  ~/.inputrc, else /etc/inputrc. C-x C-r (re-read-init-file) runs the
  same lookup on top of the current state, resetting nothing.
- Lines: comments, directives, `set`, key bindings (`"seq"` with
  readline's escapes, or a key name with its substring-matched
  modifiers), `:=` ignored, CR stripped only in msys mode. Errors as
  readline's, `readline: FILE: line N: MSG`, losing the location after
  an `$include` as readline does. `$if` (term, mode, version, the
  application, variable tests), `$else`, `$endif` with one stack for
  the process, `$include` capped at 32 deep.
- Variables: all of readline's, case-insensitive, with readline's
  setters and errors and `bind -v`'s printed forms for `$if`. Those
  with an effect here: the completion settings, bell-style (none,
  visible as a flash), comment-begin, keyseq-timeout (0 waits forever),
  isearch-terminators, search-ignore-case (isearch, non-incremental and
  prefix searches), enable-bracketed-paste, force-meta-prefix and
  convert-meta (a meta key bound as ESC and the key), history-size
  (stifles the list, HISTSIZE untouched), bind-tty-special-chars. The
  rest are kept (issues.md).
- Keymaps: emacs, emacs-meta and emacs-ctlx are nodes of the one trie;
  the vi maps are sinks. The keymap is reset after each read.
- Bindings: macros (the text fed back ahead of the terminal), unknown
  functions binding nothing, a longer sequence keeping the prefix's own
  binding as its shadow (run, and the key pushed back, when the next key
  is not bound under it, or after keyseq-timeout), do-lowercase-version
  dropped under a new child and falling back to the shadow; C-x A-Z are
  do-lowercase-version as in readline's C-x map.
- The terminal's erase, kill, lnext and werase are bound again on each
  line over any inputrc binding.
- t/edit 035-044 (recorded with bash 5.3): every error message, key
  names and sequences, tty characters, conditionals, includes, re-reads
  with INPUTRC and history-size, values and keymaps, and the completion
  settings (case, marks and layout, show-all, disable, skip-completed,
  menu completion). The CRLF case is not recorded: msys strips the CR,
  POSIX keeps it.

### Step 7: POSIX terminal

Most of it came with steps 1 and 2 (termios raw mode taken from the
terminal's current state on each line and restored after it, so
programs run cooked and keep what they set; SIGWINCH; the size), and
every t/edit script has been checked on a pty against bash since.

- The terminal database: readline draws as on a dumb terminal when
  termcap knows no such terminal. On POSIX an unset or empty TERM, or
  one with no terminfo entry (TERMINFO, ~/.terminfo, TERMINFO_DIRS,
  /etc/terminfo, /lib/terminfo, /usr/share/terminfo, by first letter or
  its hex code), is dumb, checked on each line since bash resets the
  terminal when TERM changes. Windows needs no TERM: only TERM=dumb.
  The vos has entries for xterm, xterm-256color, dumb and vt100.
- The terminal's special characters from the last line become
  self-insert before this line's are bound, as readline does.
- bell-style visible flashes reverse video; screens agree with bash's
  (no bell); the bytes differ from termcap's vb only by its delay.
- t/edit 045 (TERM unset, unknown, known) and 046 (bell styles); the
  whole corpus (046 scripts) passes on the vos and, with the POSIX
  build, on a pty in the oracle container.

### Step 8: Win32 console (design)

- Output on a console without VT processing (`Tty.legacy`): the
  editor's bytes (edflush) go through `vtcon.cpp` in the core instead
  of fd 2. It keeps a parser state per editor, passes text and the
  controls the console processes itself (CR, LF, BS, BEL) to the
  console, and turns the escapes the editor emits (CUU/CUD/CUF/CUB,
  CUP to home, EL, ED 0/2, SGR 0/7/27; private modes and OSC ignored)
  into a few primitives, `os_con(Os *, Handle, ConOp *)`: CON_INFO
  (buffer size, window rows, cursor, attribute), CON_MOVE, CON_WRITE
  (UTF-8 text at the cursor, the console wrapping and scrolling),
  CON_FILL (blanks from a cell, for a count, with an attribute),
  CON_ATTR (the attribute for writes). Reverse video swaps the
  foreground and background nibbles, as busybox does. Only the editor
  uses it; other programs' escapes are theirs.
- The vos implements os_con over its VTerm, and every t/edit script
  runs a second time with the terminal reporting legacy, through
  vtcon, against the same .screens (the VTerm keeps the script's
  deferred wrap, which a real legacy console lacks; the editor then
  uses width-1, tested by the nowrap scripts).
- Input on a console without VT input: the Win32 layer reads
  ReadConsoleInputW and a core function turns each key event into
  xterm bytes (arrows, Home/End/Insert/Delete/PgUp/PgDn with readline's
  modifier forms, Alt as an ESC prefix, AltGr as text, Ctrl+Space and
  Ctrl+@ as NUL, VK_PACKET and surrogate pairs as UTF-8, key-up events
  only for Alt+numpad), unit tested from tables.
- WINDOW_BUFFER_SIZE_EVENT raises SIGWINCH in both input modes.

### Step 8: Win32 console (done)

- vtcon.cpp as designed above. SGR goes further than the editor needs,
  for prompts: bold, the 16 colors and reverse, as busybox maps them
  to console attributes; the vos model decodes reverse and bold. All
  46 t/edit scripts pass a second time through vtcon.
- Raw-mode console reads use ReadConsoleInputW in both modes: with VT
  input the characters the console made, without it conkey's
  conversion; WINDOW_BUFFER_SIZE_EVENT raises SIGWINCH while the read
  goes on, waking the editor through the scheduler. Ctrl-Z in raw mode
  is a key, not end of file. conkey has table tests (main_test.cpp).
- winctl on Win11 conhost (VT): typing, arrows with Ctrl and Alt,
  history, Home, Ctrl-C, a resize between and during lines (COLUMNS,
  the long line redrawn after the console reflowed it), Ctrl-C claimed
  by a shell started with it ignored (its child keeps the ignore, as
  bash's), completion_strip_exe in msys mode. On the XP laptop's legacy
  console: the same keys through conkey, a line wrapping at width-1
  and edited across the wrap, a completion list, reverse-i-search's
  reverse video, C-g, C-l.


### Step 9: editor fuzzer

- The property lives in the vos, so the t/edit specs check it too:
  test and fuzz layers define EDIT_CHECK, and edit.cpp calls
  `edcheck` when a line starts (after its first output is flushed),
  when a redraw starts from the left margin (edredraw), and after every
  redisplay. vos.cpp's edcheck draws the editor's layout (`shown`) on
  a blank vterm, as tall as the layout plus the screen, row by row with
  one parser (attributes carry across rows as they do on the screen),
  and compares every cell from the prompt's row (cursor row minus
  `crow`) to the bottom of the screen: rows past the line must be
  blank. The cursor must be at point (`prow`, `pcol`) with no wrap
  pending, and the editor's idea of it must agree. A space on an
  otherwise blank cell counts as blank (the space that makes the
  terminal wrap after a full row).
- Not checked, as readline draws them wrong too: a line that started
  past the left margin (output with no final newline) or with
  attributes on, until a redraw from the margin; a line that ever got
  taller than the screen (its top scrolled away, and moving up stops
  at the top row), until the same; TERM=dumb's sideways scrolling; a
  resize the editor has not seen yet; a tab in the prompt (counted as
  one column, as readline counts it), which the fuzzer's prompts avoid.
- `FUZZ_EDIT` (main_fuzz.cpp, fuzzedit): a header byte picks deferred
  wrap, a legacy console (vtcon through os_con), TERM=dumb, one of
  eight prompts (empty, longer than a narrow screen, invisible SGR and
  title sequences, \u@\h and \w, wide characters, two lines, a
  combining mark) and the C or UTF-8 locale; two bytes the size (4-80
  columns, 1-24 rows). The rest are keys, with FF FE R C resizing and
  FF FD N pausing N*10 ms (the key sequence timeout). Commands typed
  run on the vos like any fuzzed script. A failure traps under AFL;
  replay builds print both screens.
- The editor's arenas are sized from the shell's reserve, capped at 16
  MiB each, so a small fuzz heap holds them.
- `tools/fuzz edit` seeds a dozen sessions: typing, motion, kill and
  yank, completion lists, i-search, history, wide characters across
  wraps, a resize, a pause before ESC, cd changing \w, TERM=dumb,
  bracketed paste.
- Found by the first campaign (45 minutes, 8 cores), all fixed:
  - A lone UTF-8 lead byte at the end of the line was laid out as a
    column while the terminal held it back, waiting for the rest; any
    byte starting no valid sequence (and a C1 control, which terminals
    do not show) is now drawn as U+FFFD, one column, as a terminal
    shows readline's raw bytes. A byte breaking a sequence in
    self-insert is a key of its own instead of being dropped, so typed
    bytes can join into one character around point: the cursor goes
    after it.
  - Deleting a combining mark left it on the screen: the row's cells
    compared equal up to the shorter row with the same width. The
    redraw now starts from the cell a zero-width one sits on.
  - i-search showed a control character in its string raw, which the
    prompt counts as a column and the terminal does not show: it is
    shown as ^X, as on the line.
  - C-l with an argument and redraw-current-line drew the line again
    over the old without clearing it (the `(arg: 5) ` prompt was left
    behind): both clear the line's rows first, as readline's
    rl_refresh_line, shared with the resize.
  - shell-expand-line took its scratch from the next capture depth,
    which a command substitution in the line reused, overwriting the
    expansion's state (a trap): it claims the depth as captures do.
  - An expansion error in shell-expand-line left the line in place
    under the message; bash abandons the line and starts a new prompt
    with status 1 (t/edit/047, recorded): editline's new ED_ABORT.
  - On a legacy console the check's reference had underline, which
    vtcon cannot draw.
