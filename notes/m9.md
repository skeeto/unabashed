## Where things stood at the start (bf02049)

- unabashed builds with one g++ command per target (Makefile), x64 and
  i686, kernel32 imports only, PE subsystem 5.02/5.01. The persona
  comes from argv[0]: sh, ash and lash (any case, .exe or not) are
  native mode, anything else msys mode (bash), and an etc/fstab beside
  the install root forces msys mode.
- tools/w64trial (M5a) already mirrors a w64devkit with our shell as
  sh.exe and builds autoconf projects with it: make 4.4.1 and xz 5.6.4
  configure, build and pass `make check`, with equal configurations.
- w64devkit (~/src/w64devkit, master at 667d0d3) builds in Docker
  (Debian trixie, GCC 16.2 cross compilers built in the image). Its
  shell is busybox-w32: bin/sh.exe, ash.exe, lash.exe and the other
  applets are copies of busybox-alias.c, a stub that starts busybox.exe
  with the same command line; w64devkit.exe (src/w64devkit.c) starts
  `busybox.exe` with the command line `sh -l`. The kit's pages are
  hand-written man(7) under man/, formatted by the kit's nroff and
  shown by busybox man; man/README.md is the style guide.
- No w64devkit build cache in WSL's docker: a release build downloads
  every source (GCC, binutils, mingw-w64, gdb, ...) and builds the
  cross toolchain, hours of work.


## Principles

1. w64devkit is the user's project: changes go on a branch there
   (`unabashed`), committed but not pushed or merged, each step tested
   on a local kit before it is committed.
2. Nothing in w64devkit's tree depends on unabashed being published:
   the Dockerfile takes the source as a tarball like every other
   dependency, and where that tarball comes from (a release URL and
   its sha256) is the user's decision, left as a marked placeholder.
3. The man page is our own words, written from our code and behaviour,
   never from bash's manual (GPL), in the kit's man(7) style.
4. The busybox applets stay; only the shell names move. busybox's own
   `sh` applet remains reachable as `busybox sh`.


## Steps

1. **Release build and names.** A `make dist` source tarball (git
   archive, no tests' bash files), and the release build lines the
   Dockerfile uses (the same flags as the Makefile's). How the four
   names are installed: each a copy of the one image (the persona
   needs argv[0], and make starts `sh -c` per recipe line, so a stub's
   extra process would cost every line; 7z's solid archive stores the
   copies once).
2. **Launcher.** w64devkit.c starts bin/sh.exe with `sh -l`, and
   busybox only if sh.exe is missing; the alias list loses sh, ash and
   lash; etc/profile (busybox-specific comments, libtool workaround)
   checked under our shell.
3. **Man page.** man/man1/unabashed.1 in the kit's style: invocation
   and the personas, the Windows path rules of each mode, options,
   startup files, environment, what differs from bash, exit status;
   stubs bash.1, sh.1, ash.1 and lash.1. Lint clean with the kit's
   nroff -w (and groff/mandoc if their images are at hand).
4. **Kit trial.** A local kit mirrored from the installed w64devkit
   with the branch's launcher, our four names and the new page: an
   interactive session from w64devkit.exe driven by winctl (profile,
   prompt, editing, man, Ctrl-C, exit), make and configure of local
   projects, busybox sh absent from the process tree; the i686 build
   on the XP laptop the same way.
5. **MSYS2 programs and bridges.** The M9 issues: study what Cygwin
   programs accept for a procsub's path and for descriptors above 2;
   fix what is reachable, accept the rest with reasons.
6. **Dockerfile.** A build-unabashed stage on the branch, for both
   variants, from the tarball of step 1; checked by running the same
   commands with the kit's own compilers. A full release build waits
   for the user (downloads and hours of toolchain building).
7. **Closing.** Exit criteria checks, issues.md has no M9 items.


## Exit criteria checks

1. A kit with the branch's changes starts unabashed from w64devkit.exe
   and runs make, configure and interactive use with no busybox shell
   (Windows 11 and XP).
2. sh, ash and lash are no longer busybox aliases in the Dockerfile.
3. No regressions: the suites as at M8's close.
4. No M9 items left in issues.md.


## Implementation

### Step 1: release build and names

- `make dist` writes `unabashed-YYYYMMDD-HASH.tar.gz` (git archive of
  HEAD, prefix `unabashed-YYYYMMDD-HASH/`, 2.2 MB, ignored by git).
  Built from the extracted tarball with the cross compilers' names, as
  the Dockerfile will (`x86_64-w64-mingw32-g++` and
  `i686-w64-mingw32-g++`, the Makefile's FLAGS and WIN32, plus the
  i686 subsystem and large-address flags): kernel32 imports only, 1.41
  MB and 1.24 MB, 23 s for the x64 build on this machine.
- README's build line lacked the 16 MiB stack (`--stack,0x1000000`)
  that main_win32.cpp's header and the Makefile give.
- The names are four copies of one image (sh, ash, lash: native mode;
  bash: msys mode), decided in Steps above.
