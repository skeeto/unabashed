### Namerefs (vars.cpp)

- `Value` of a nameref holds the target name in `str` with `V_NAMEREF`.
  `rawlookup` is the binding itself; `lookup`, `getvar` and `getparam`
  follow namerefs.
- `resolveref(sh, name, global)` follows a chain as bash's
  `find_variable_nameref`: at most 8 links ("maximum nameref depth (8)
  exceeded"), a link back to the start or to itself warns "circular
  name reference" and names nothing, except inside a function when the
  variable found is local: then the global binding (`Ref.global`). A
  value `a[sub]` ends the chain with `hassub`. `global` follows only
  global bindings (`declare -g`).
- Assignments use `assignref`, bash's `bind_variable`: when the first
  non-temporary binding of the name is a function's, a nameref there is
  followed scope by scope downward (`bindingat`), each scope as far as
  its own table goes; a loop within one scope exceeds the depth and the
  global variable of the name itself is assigned (this is why
  `typeset -n v=v; v=x` in a function prints both warnings and sets
  the global `v`). Outside functions it is the dynamic chain. A nameref
  without a value takes the assigned value as its target (`declare -n
  r; r=x`), which must be a valid name ("not a valid identifier"
  prefixed by the running builtin, `Shell.bltname`); a readonly one
  fails silently. `anyref` keeps the walk off the fast path: only a
  name with a nameref somewhere in its binding stack pays.
- A target `a[sub]` assigns the element; if `a` is itself a nameref, it
  loses the attribute with bash's warning (global scope only, as bash).
- Arrays: `arraytarget` maps a name to what a nameref names for element
  and list assignments, `read -a`, coprocs and `unset name[sub]`. A list
  given to an empty nameref removes the attribute ("removing nameref
  attribute"); an element of an empty nameref, or a list for a nameref
  to an element, is "not a valid identifier".
- Expansion: `${!ref}` is the last nameref's value; `$ref` for a target
  `arr[@]` expands as `"${arr[@]}"` (getparam returns the list).
- `declare`: `-n` checks self references (an error at global scope, two
  warnings in a function), invalid targets, arrays, readonly targets,
  `ref+=x` self references; without `-n` it acts on the target, in a
  function only through a nameref of the function's own (bash's
  `declare_transform_name`); `+n` follows to the end, assigns there and
  clears the attribute; `-n` on an integer evaluates the name to a
  number and quietly deletes the new variable, as bash.
- `unset` follows (an element target included), `unset -n` touches only
  namerefs; `for` with a nameref variable re-targets it each iteration;
  temporary bindings (`ref=x cmd`) and children's environments bind the
  target (`tempname`); `test -R` looks at the name itself.

### Arrays and associative arrays

- Associative key-value lists (`A=(k v k v)`) expand each word as an
  assignment value: no splitting, no globbing (`$foo` with a space is
  one key, `*` stays `*`).
- `declare name[sub]='(...)'` (quoted) follows bash's rules: an element
  of an existing array, a whole list for `-a`/`-A` or an existing array
  given without a subscript, an element plus the "quoted compound array
  assignment deprecated" warning for a new variable; a literal
  `name[sub]=(...)` is "cannot assign list to array member".
- `${#a[bad]}` reports `[bad]: bad array subscript` and ends the
  command; `${a[bad]}` and `${!a[bad]}` report `a: bad array
  subscript` and go on.
- `${A[@]:=x}` on an associative array assigns key `@`.
- assoc_expand_once/array_expand_once: a builtin's argument (printf -v,
  read, wait -p) keeps its subscript as it is (`SV_RAWKEY`; an indexed
  one is evaluated without expansion, its errors abandoning the command
  and `-c` text like other subscript errors). An unquoted `name[sub]`
  argument (compargs 3, `onewordarg`) of an associative array may hold
  brackets, the key running to the last `]`; declare parses
  `name[key]=` flat, the key ending at the first `]` (`splitrefflat`).
  `let` takes associative keys as they are. `test -v`, `unset` and
  `declare name[sub]=` evaluate indexed subscripts without expansion.
- A subscript may hold a substitution with brackets:
  `a[$(echo ])]=x` (parse.cpp `skipsubscript`).
- In arithmetic, literal brackets of a subscript are not quoted by
  `arithsubscript` (`$(( a[a[0]] ))`), only those an expansion produced.
- A new local's list expands with the caller's variable still visible
  (`local -a arr=("${arr[@]}")`: `SV_NEWLOCAL`, `hidelocal`).

### Dynamic variables and listings

- DIRSTACK (the working directory alone until pushd exists),
  BASH_ALIASES and BASH_CMDS are dynamic: read, they are built as bash
  builds them, the alias and command tables walked in bash's bucket
  order (64 and 256 buckets, FNV-1) into associative arrays of the same
  size, so `${!BASH_ALIASES[@]}` comes out in bash's order (`Alias.seq`
  records definition order for the alias table's chains). Assigning an
  element defines an alias or remembers a path; unsetting one changes
  neither table, as in bash.
- SHELLOPTS and BASHOPTS are readonly dynamic variables (the options on,
  in listing order). Inherited from the environment, they turn their
  options on; exported, children get the current value.
- Full listings (`set`, `declare -p` with no names) show what bash
  shows: dynamic scalars (LINENO, RANDOM, SECONDS, BASHPID, EPOCH*,
  BASH_COMMAND, BASH_SUBSHELL, BASH_ARGV0, HISTCMD, COMP_WORDBREAKS)
  valueless until first read (`Shell.dynread`), then RANDOM and LINENO
  with their last values; GROUPS empty until read; DIRSTACK,
  BASH_ALIASES, BASH_CMDS, BASH_ARGV, BASH_ARGC as `()`; PIPESTATUS
  absent until a command has run. Named (`declare -p LINENO`) they are
  computed, as in bash. LINENO is not an integer; OPTIND is.
  BASH_LOADABLES_PATH has bash's default.
- `readonly` and `export` listings use the `declare -..` form, and in
  POSIX mode `readonly -a name=...`/`export name=...` (only -a and -A
  shown). `local -p name` shows only the function's own locals.
  `readonly name[sub]` is an invalid identifier; `declare +a` and other
  attribute changes on a readonly variable are "readonly variable".
- `declare -f`/`-fp` of a missing function: `-fp` reports "not found".

### Temporary bindings and scope

- `var=x export var` / `readonly` / `declare -x` outside a function: the
  temporary value and attributes reach the binding beneath
  (`belowtemp`: the next binding, which may be a function call's own
  temporary, or a new global). Inside a function, operations on the
  call's temporaries do not propagate.
- A local made while a temporary binding for the declaring builtin
  exists takes its value (`var=value declare -x var` in a function).
- A local declared without a value hides nothing from programs: the
  environment gets the binding beneath.
- `declare -I`/`local -I` inherit the hidden value and attributes.
- localvar_unset: unsetting a caller's local leaves it unset but local.
- `set -k`: assignment words anywhere in a simple command are
  assignments.
- `IGNOREEOF` and `set -o ignoreeof` follow each other, including when
  `local -` restores the options.
- POSIX mode: assignments before a special builtin persist exported.
- `name[sub]=x cmd`: reported as not a valid identifier and skipped;
  the command runs.
- Inherited environment entries that name no variable (`v[0]=x`) are
  passed on to programs (`Shell.badenv`).
- `compgen -A shopt` and `-A setopt` list the option names.

Benchmarks (bench/run, Linux in WSL, against bash 5.3): new `b3`
(indexed arrays; 1.9 s against bash's 191 s at n=1e6, now n=3e5 so bash
finishes) and `b4` (associative arrays, 0.47 s against 1.30 s); b1, b2,
b9 and b10 unchanged by the nameref checks on assignment.

### Decisions

- `DIRSTACK` holds only `$PWD` until pushd/popd/dirs exist (M7).
- Listings show dynamic scalars other than RANDOM and LINENO with their
  current value once read, where bash shows the value from the last
  read.
- `refwarning` and other messages from code without a scratch arena use
  a 1 KiB stack arena with names cut at 256 bytes.
- Assigning through a nameref into a binding of a lower scope that is
  shadowed by a newer one assigns the visible binding (bash would
  assign that scope's own); a full fix needs assignment at a given
  depth.

### Status

The cond oracle passes (53 of 86 run-* now). new-exp has no `=~`; what
it lacks is indirection and pattern substitution (other areas).

Differential testing against glibc 2.41 (Debian, WSL): the generated
cases of `regex_diff --random` (patterns of glibc-sensitive pieces,

short line): 1.1 s against 2.6 s. A 10000-byte subject with `(a|b)*x$`
300 times: 0.42 s against 0.36 s (three linear passes where glibc makes
one or two).

### Shell side

- The right side is expanded with quote flags, then quoted as bash's
  `quote_string_for_globbing` does for a regexp (`expandregex`): a
  quoted ERE special gets a backslash; inside an unquoted bracket
  expression quoted characters stay as they are; bash's class,
  equivalence and collating states carry from one bracket to the next;
  an unterminated bracket is rescanned as text; a `[` right after a
  \001 byte opens no bracket (bash sees it CTLESC-quoted).
- `condregex`: compile with `REX_ICASE` under nocasematch and
  `REX_UTF8` in a UTF-8 locale. An invalid regexp prints `[[: invalid
  regular expression `RE': MSG` with glibc's message and gives 2. Then
  BASH_REMATCH is found or made as `read -a` makes its array (global
  when new, a local one if visible, namerefs followed; readonly reports,
  associative is "not an indexed array"), emptied, and on a match
  filled: unset groups are empty strings, an unclosed group (glibc can
  leave `eo` at `-1`, offset by the start) copies to the end, as bash's
  `strncpy` does.
- `condeval` returns a status: 2 from `=~` or a bad `-t` operand (now
  `[[: X: integer expected`, as bash) passes `&&` as failure, `||` and
  `!` treat it as false, as bash's `execute_cond_node`.

### regex.cpp

- The parser follows glibc's `parse_reg_exp`/`parse_branch`/
  `parse_expression`/`parse_dup_op`/`parse_bracket_exp` token by token,
  so errors come out in glibc's order with glibc's codes; messages are
  `rxerrors`. Intervals expand as glibc's (`e{n,m}` = n copies then
  `((e?)e)?...`), the first optional copy of a group marked optional and
  later copies not (glibc's `duplicate_tree` clears the mark); a group
  whose body is a group merges as `optimize_subexps`; back-references
  to groups of other alternatives are invalid.
- Nodes are numbered in glibc's postorder (CONCAT nodes unnumbered) and
  forks keep glibc's sorted edests: where glibc may go two ways it takes
  the lower-numbered node, so `(|a)` prefers `a`.
- `rxeclosures`/`rxdupclosure` replay glibc's `calc_eclosure` and
  `duplicate_node_closure`: the nodes after an anchor are copied with
  the anchor's constraints, in glibc's order and numbering, including
  `search_duplicated_node` reuse and the tie back to the anchor. glibc
  marks every node of an interval copy "duplicated", so anchors inside
  copies get no copies; regex.cpp does the same (`dup`).
- Matching: `rxpike` finds the leftmost start and longest end with a
  Pike VM whose states are glibc's: whole static closures, nodes whose
  constraints on the preceding character fail marked unusable.
  `rxlastnode` finds glibc's `last_node` (the lowest-numbered end node
  copy that may end the match), `rxsift` glibc's sifted states, and
  `rxwalk`/`rxproceed` replay `set_regs`/`proceed_next_node` (fork rule,
  `update_regs` with the optional-group undo, the fail stack and its
  early return when a node repeats, used with back-references).
- Back-references: `rxlongest` searches every path (plain registers:
  the automaton has no optional-group undo), cutting empty loops by the
  walk's fork rule; a budget bounds it in the fuzz harness only.

### glibc's quirks reproduced

- No REG_NEWLINE, yet `^` matches after a newline the match consumed and
  `$` before one it goes on to consume (`a$.` matches `a\nb`), as the
  automaton's transitions on `\n` use the newline context. Sifting does
  not allow the latter, so with groups and forks such a match is
  rejected and the search goes on (`(a$.|a)` fails on `a\nb`); without
  forks the walk fails and so does the whole match (`(a)$.`).
- An empty match at a start where the automaton then stays in its
  initial state is reported where glibc's skip-ahead stopped:
  `a*\B` on `ca.` gives (2,2) (`rxstall`).
- A start whose match sifting cannot place is abandoned and the search
  goes on from the next position.
- `(^a)+` never matches `aa`, `(\ba)+` matches it whole: anchors in the
  `+`/interval copy filter only themselves.
- glibc's `get_subexp` takes the lowest-numbered close node of a group
  in a state: a back-reference to a group copied by an interval cannot
  see spans closed by a later copy at the same position, so
  `(a?){2}\1` never matches (`copies`, two-pass `rxlongest`).
- Matches may start inside a UTF-8 character (glibc's first-byte check
  is always true at the start of its rebuilt buffer).
- `[[.space.]]` and other named collating symbols are invalid (no
  collation rules in C and C.UTF-8); `[[=ab=]]` likewise; `[[:word:]]`
  and `[[:ascii:]]` are not classes; under REG_ICASE `[Z-a]` is an
  invalid range (`[Z-A]`) and an escaped lowercase letter (`\a`) never
  matches, since glibc upper-cases the pattern but not escapes.

### Known differences (deliberate or not yet done)

- Back-references in patterns with repetition: glibc decides which
  spans a back-reference may use with a path-insensitive search
  (`get_subexp`, `check_arrival`, `sift_states_bkref`,
  `check_dst_limits`) that regex.cpp approximates by an exact path
  search. Nested stars and empty iterations before a back-reference
  (`(a*)*...\1`) then sometimes give other registers or another
  verdict. The harness skips such patterns (back-reference plus
  `* + ? {`); plain ones are compared.
- UTF-8 classes, `\w`, word boundaries and case folding are ASCII-only
  (glibc uses iswctype/towupper): `[[:alpha:]]` does not match é.
- Size: patterns whose tree would pass 2^20 nodes (`(a{100}){100}...`,
  a chain of 20 `+`) are "Memory exhausted" (code 12), where glibc
  allocates on; nesting deeper than 500 groups likewise, for the stack.
- Every `=~` compiles afresh, as in bash; no cache.

### glob.cpp

- Follows bash's `glob_filename`/`glob_vector`: split at the last slash
  (with extglob the last one outside groups, `glob_dirscan`), expand
  the directory part the same way, then match the last component in
  each directory found. A component without glob characters (bash's
  `glob_pattern_p`: a bracket may span slashes, `+(`, `@(` and `!(`
  count even with extglob off) is checked with lstat after a stat of
  its directory, never listed; that finds dangling links and names in
  unreadable directories.
- `**` (globstar): `GX_ALLDIRS` lists every name below the directory,
  entering directories but not links to them (lstat); `GX_ADDCUR` adds
  the directory itself (`a/**` gives `a/`), as a "" placeholder from a
  null directory. A leading run of `**/` and a trailing run collapse
  as bash does; `**/**` is `**`; a link to a directory met by `**/` is
  listed (`link/`) but `**/x` does not look inside it. `**/a/**` lists
  names more than once, as bash does.
- The order before sorting is bash's: each directory's matches in
  reverse listing order, `.` and `..` listed first.
- Each directory is listed at most once per expansion (`GlobDir`,
  keyed by its path as written), and an entry's type comes from the
  listing (`Dirent.type`), so stats happen only for a link, a literal
  component or a trailing slash. Component patterns are compiled once
  per directory (`globprog`, `progmatch`).
- GLOBIGNORE: patterns split at colons outside brackets and extglob
  groups (and quotes and backslashes), as `skip_to_delim` does; command
  substitutions in the value are not skipped. Each pattern matches the
  whole path with PM_PATHNAME (bash's trailing-star quirk included);
  `.` and `..` as the last component always go.
- GLOBSORT (bash 5.3): name (the default), size, mtime, atime, ctime,
  blocks, numeric, nosort; a leading `+` is ignored and `-` reverses;
  nothing after the sign means name; any other value is the default.
  Ties break by name in the same direction; numeric compares all-digit
  names by value (saturating) and puts them first, equal values keeping
  their order (glibc's qsort is a merge sort; ours is stable). A failed
  stat sorts as -1. Names compare by byte (strcoll in C and C.UTF-8).
- nullglob, failglob, dotglob, nocaseglob and globskipdots as before;
  spec 768 covers failglob in groups, functions, comsubs and `for`.
- Redirection words are not split in POSIX mode, nor globbed there
  unless interactive (bash's W_NOGLOB in redir.c); `$(< file)` expands
  its word as a redirection's (it used `expandstring`: no globbing).

### pattern.cpp and expansions

- `patprog`/`progmatch`: a pattern compiled once, byte-wise and wide,
  for matching many strings.
- `patsearch`/`searchnext`: `${x//p/r}` searches one string in one
  pass: the pattern, the string's context and, for a pattern of varying
  length, every match start (one reversed match) are computed once, so
  each search costs what it examines. Patterns where `findspan` probes
  or tests for any match first take `patfind` on each remainder, as
  before. `pattern_test` checks it against `patfind` on every golden
  `/` and `//` case.
- `${x//p/r}` searches again only while text remains (no empty match
  after a match that reaches the end); after an empty match it copies a
  whole character in UTF-8 (one byte when invalid), as bash's
  `COPY_CHAR_P`; nocasematch applies to it (not to `#` and `%`).
- Divergent brackets (whose end depends on the element that matched)
  fork with the rest of the pattern compiled once per place
  (`PatRest`), so up to `PAT_MAXFORKS` (10) of them in one sequence
  match as bash; the limit was 4, with the rest compiled per
  alternative.

### vos and platform

- `Stat` gains `ctime` and `blocks`: from stat on POSIX; on Win32 ctime
  is mtime and blocks come from the size in 4 KiB clusters; the vos
  tracks ctime on creation, writes, chmod and utime, and counts blocks
  as ext4.
- The vos checks search permission on every directory a lookup passes
  and read permission for listings (the owner's bits for the user's
  nodes, the others' bits otherwise), and lists a directory newest
  first, as tmpfs does where specs are recorded.
- printf (b_printf.cpp) took working memory from a copy of the arena
  its output grew into, so long `%q` and `%b` output was overwritten;
  it now allocates ahead of the output in the output's own arena.

### Differential testing against glibc

`pattern_diff --random` generates the cases bash can show (case and
`[[ ]]` with extglob; a pathname component with FNM_PATHNAME and
FNM_PERIOD; a GLOBIGNORE path with FNM_PATHNAME), with nocase and
UTF-8 variants, and compares `patmatch` with `fnmatch`. Differences
were triaged by running them through bash 5.3 (pattern_oracle.bash in
the container; its new `i` kind tests GLOBIGNORE on real paths). bash
agreed with pattern.cpp everywhere but one class, now fixed (forks,
above). The classes where bash and glibc differ are skipped
(`knowngap`):
- a trailing unpaired backslash;
- extglob groups;
- under FNM_PATHNAME, a final run of `*` and `?` with a star matching
  slashes, and `**` or `*?` failing where the string has a slash;
- a bracket holding a slash under FNM_PATHNAME;
- `[. .]` and `[= =]`, also after a backslash;
- an unknown, unterminated or range-adjacent `[:x:]`;
- glibc failing a bracket after `*?` under FNM_PERIOD;
- non-ASCII in UTF-8 with classes, case folding, brackets, `?` or
  invalid bytes;
- a fork between stars (see below).

With those, tens of millions of random cases agree. AFL (`tools/fuzz
pattern` in ~/fuzz-pattern, 2 cores, 20 plus 10 minutes, about 7
million runs; the WSL VM restarted by itself during the first run)
saved 82 differences: the one real class, and the rest in the classes
above once checked with bash.

### Known differences and decisions

- A divergent bracket between stars: bash's star loop commits to the
  first place the part before the next star matches (glibc's cut,
  exact only when a bracket ends in one place), so `*[*[-\[..]*]` does
  not match `*c` in bash; pattern.cpp tries every place and matches.
  Only malformed brackets get here.
- More than 10 divergent brackets in one sequence are not forked (the
  bracket is read as the element scan sees it), to keep compiling and
  matching bounded.
- Classes and case folding are ASCII-only, as before.
- No Big5 or other non-UTF-8 multibyte locale.
- Globbing does not check for Ctrl-C between entries, where bash does.
- GLOBIGNORE splitting skips quotes and groups but not `$(...)`.
- GLOBSORT=nosort gives bash's construction order over the platform's
  listing order, which differs between file systems.
