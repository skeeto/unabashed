### Namerefs (vars.cpp)

- `Value` of a nameref holds the target name in `str` with `V_NAMEREF`.
  `rawlookup` is the binding itself; `lookup`, `getvar` and `getparam`
  follow namerefs.
- `resolveref(sh, name, global)` follows a chain as bash's
  `find_variable_nameref`: at most 8 links ("maximum nameref depth (8)
  exceeded"), a link back to the start or to itself warns "circular
  name reference" and names nothing, except inside a function when the
  variable found is local: then the global binding (`Ref.global`). A
  value `a[sub]` ends the chain with `hassub`. `global` follows only
  global bindings (`declare -g`).
- Assignments use `assignref`, bash's `bind_variable`: when the first
  non-temporary binding of the name is a function's, a nameref there is
  followed scope by scope downward (`bindingat`), each scope as far as
  its own table goes; a loop within one scope exceeds the depth and the
  global variable of the name itself is assigned (this is why
  `typeset -n v=v; v=x` in a function prints both warnings and sets
  the global `v`). Outside functions it is the dynamic chain. A nameref
  without a value takes the assigned value as its target (`declare -n
  r; r=x`), which must be a valid name ("not a valid identifier"
  prefixed by the running builtin, `Shell.bltname`); a readonly one
  fails silently. `anyref` keeps the walk off the fast path: only a
  name with a nameref somewhere in its binding stack pays.
- A target `a[sub]` assigns the element; if `a` is itself a nameref, it
  loses the attribute with bash's warning (global scope only, as bash).
- Arrays: `arraytarget` maps a name to what a nameref names for element
  and list assignments, `read -a`, coprocs and `unset name[sub]`. A list
  given to an empty nameref removes the attribute ("removing nameref
  attribute"); an element of an empty nameref, or a list for a nameref
  to an element, is "not a valid identifier".
- Expansion: `${!ref}` is the last nameref's value; `$ref` for a target
  `arr[@]` expands as `"${arr[@]}"` (getparam returns the list).
- `declare`: `-n` checks self references (an error at global scope, two
  warnings in a function), invalid targets, arrays, readonly targets,
  `ref+=x` self references; without `-n` it acts on the target, in a
  function only through a nameref of the function's own (bash's
  `declare_transform_name`); `+n` follows to the end, assigns there and
  clears the attribute; `-n` on an integer evaluates the name to a
  number and quietly deletes the new variable, as bash.
- `unset` follows (an element target included), `unset -n` touches only
  namerefs; `for` with a nameref variable re-targets it each iteration;
  temporary bindings (`ref=x cmd`) and children's environments bind the
  target (`tempname`); `test -R` looks at the name itself.

### Arrays and associative arrays

- Associative key-value lists (`A=(k v k v)`) expand each word as an
  assignment value: no splitting, no globbing (`$foo` with a space is
  one key, `*` stays `*`).
- `declare name[sub]='(...)'` (quoted) follows bash's rules: an element
  of an existing array, a whole list for `-a`/`-A` or an existing array
  given without a subscript, an element plus the "quoted compound array
  assignment deprecated" warning for a new variable; a literal
  `name[sub]=(...)` is "cannot assign list to array member".
- `${#a[bad]}` reports `[bad]: bad array subscript` and ends the
  command; `${a[bad]}` and `${!a[bad]}` report `a: bad array
  subscript` and go on.
- `${A[@]:=x}` on an associative array assigns key `@`.
- assoc_expand_once/array_expand_once: a builtin's argument (printf -v,
  read, wait -p) keeps its subscript as it is (`SV_RAWKEY`; an indexed
  one is evaluated without expansion, its errors abandoning the command
  and `-c` text like other subscript errors). An unquoted `name[sub]`
  argument (compargs 3, `onewordarg`) of an associative array may hold
  brackets, the key running to the last `]`; declare parses
  `name[key]=` flat, the key ending at the first `]` (`splitrefflat`).
  `let` takes associative keys as they are. `test -v`, `unset` and
  `declare name[sub]=` evaluate indexed subscripts without expansion.
- A subscript may hold a substitution with brackets:
  `a[$(echo ])]=x` (parse.cpp `skipsubscript`).
- In arithmetic, literal brackets of a subscript are not quoted by
  `arithsubscript` (`$(( a[a[0]] ))`), only those an expansion produced.
- A new local's list expands with the caller's variable still visible
  (`local -a arr=("${arr[@]}")`: `SV_NEWLOCAL`, `hidelocal`).

### Dynamic variables and listings

- DIRSTACK (the working directory alone until pushd exists),
  BASH_ALIASES and BASH_CMDS are dynamic: read, they are built as bash
  builds them, the alias and command tables walked in bash's bucket
  order (64 and 256 buckets, FNV-1) into associative arrays of the same
  size, so `${!BASH_ALIASES[@]}` comes out in bash's order (`Alias.seq`
  records definition order for the alias table's chains). Assigning an
  element defines an alias or remembers a path; unsetting one changes
  neither table, as in bash.
- SHELLOPTS and BASHOPTS are readonly dynamic variables (the options on,
  in listing order). Inherited from the environment, they turn their
  options on; exported, children get the current value.
- Full listings (`set`, `declare -p` with no names) show what bash
  shows: dynamic scalars (LINENO, RANDOM, SECONDS, BASHPID, EPOCH*,
  BASH_COMMAND, BASH_SUBSHELL, BASH_ARGV0, HISTCMD, COMP_WORDBREAKS)
  valueless until first read (`Shell.dynread`), then RANDOM and LINENO
  with their last values; GROUPS empty until read; DIRSTACK,
  BASH_ALIASES, BASH_CMDS, BASH_ARGV, BASH_ARGC as `()`; PIPESTATUS
  absent until a command has run. Named (`declare -p LINENO`) they are
  computed, as in bash. LINENO is not an integer; OPTIND is.
  BASH_LOADABLES_PATH has bash's default.
- `readonly` and `export` listings use the `declare -..` form, and in
  POSIX mode `readonly -a name=...`/`export name=...` (only -a and -A
  shown). `local -p name` shows only the function's own locals.
  `readonly name[sub]` is an invalid identifier; `declare +a` and other
  attribute changes on a readonly variable are "readonly variable".
- `declare -f`/`-fp` of a missing function: `-fp` reports "not found".

### Temporary bindings and scope

- `var=x export var` / `readonly` / `declare -x` outside a function: the
  temporary value and attributes reach the binding beneath
  (`belowtemp`: the next binding, which may be a function call's own
  temporary, or a new global). Inside a function, operations on the
  call's temporaries do not propagate.
- A local made while a temporary binding for the declaring builtin
  exists takes its value (`var=value declare -x var` in a function).
- A local declared without a value hides nothing from programs: the
  environment gets the binding beneath.
- `declare -I`/`local -I` inherit the hidden value and attributes.
- localvar_unset: unsetting a caller's local leaves it unset but local.
- `set -k`: assignment words anywhere in a simple command are
  assignments.
- `IGNOREEOF` and `set -o ignoreeof` follow each other, including when
  `local -` restores the options.
- POSIX mode: assignments before a special builtin persist exported.
- `name[sub]=x cmd`: reported as not a valid identifier and skipped;
  the command runs.
- Inherited environment entries that name no variable (`v[0]=x`) are
  passed on to programs (`Shell.badenv`).
- `compgen -A shopt` and `-A setopt` list the option names.

Benchmarks (bench/run, Linux in WSL, against bash 5.3): new `b3`
(indexed arrays; 1.9 s against bash's 191 s at n=1e6, now n=3e5 so bash
finishes) and `b4` (associative arrays, 0.47 s against 1.30 s); b1, b2,

### Decisions

- `DIRSTACK` holds only `$PWD` until pushd/popd/dirs exist (M7).
- Listings show dynamic scalars other than RANDOM and LINENO with their
  current value once read, where bash shows the value from the last
  read.
- `refwarning` and other messages from code without a scratch arena use
  a 1 KiB stack arena with names cut at 256 bytes.
- Assigning through a nameref into a binding of a lower scope that is
  shadowed by a newer one assigns the visible binding (bash would
  assign that scope's own); a full fix needs assignment at a given
  depth.

### Shell side

- The right side is expanded with quote flags, then quoted as bash's
  `quote_string_for_globbing` does for a regexp (`expandregex`): a
  quoted ERE special gets a backslash; inside an unquoted bracket
  expression quoted characters stay as they are; bash's class,
  equivalence and collating states carry from one bracket to the next;
  an unterminated bracket is rescanned as text; a `[` right after a
  \001 byte opens no bracket (bash sees it CTLESC-quoted).
- `condregex`: compile with `REX_ICASE` under nocasematch and
  `REX_UTF8` in a UTF-8 locale. An invalid regexp prints `[[: invalid
  regular expression `RE': MSG` with glibc's message and gives 2. Then
  BASH_REMATCH is found or made as `read -a` makes its array (global
  when new, a local one if visible, namerefs followed; readonly reports,
  associative is "not an indexed array"), emptied, and on a match
  filled: unset groups are empty strings, an unclosed group (glibc can
  leave `eo` at `-1`, offset by the start) copies to the end, as bash's
  `strncpy` does.
- `condeval` returns a status: 2 from `=~` or a bad `-t` operand (now
  `[[: X: integer expected`, as bash) passes `&&` as failure, `||` and
  `!` treat it as false, as bash's `execute_cond_node`.

### regex.cpp

- The parser follows glibc's `parse_reg_exp`/`parse_branch`/
  `parse_expression`/`parse_dup_op`/`parse_bracket_exp` token by token,
  so errors come out in glibc's order with glibc's codes; messages are
  `rxerrors`. Intervals expand as glibc's (`e{n,m}` = n copies then
  `((e?)e)?...`), the first optional copy of a group marked optional and
  later copies not (glibc's `duplicate_tree` clears the mark); a group
  whose body is a group merges as `optimize_subexps`; back-references
  to groups of other alternatives are invalid.
- Nodes are numbered in glibc's postorder (CONCAT nodes unnumbered) and
  forks keep glibc's sorted edests: where glibc may go two ways it takes
  the lower-numbered node, so `(|a)` prefers `a`.
- `rxeclosures`/`rxdupclosure` replay glibc's `calc_eclosure` and
  `duplicate_node_closure`: the nodes after an anchor are copied with
  the anchor's constraints, in glibc's order and numbering, including
  `search_duplicated_node` reuse and the tie back to the anchor. glibc
  marks every node of an interval copy "duplicated", so anchors inside
  copies get no copies; regex.cpp does the same (`dup`).
- Matching: `rxpike` finds the leftmost start and longest end with a
  Pike VM whose states are glibc's: whole static closures, nodes whose
  constraints on the preceding character fail marked unusable.
  `rxlastnode` finds glibc's `last_node` (the lowest-numbered end node
  copy that may end the match), `rxsift` glibc's sifted states, and
  `rxwalk`/`rxproceed` replay `set_regs`/`proceed_next_node` (fork rule,
  `update_regs` with the optional-group undo, the fail stack and its
  early return when a node repeats, used with back-references).
- Back-references: `rxlongest` searches every path (plain registers:
  the automaton has no optional-group undo), cutting empty loops by the
  walk's fork rule; a budget bounds it in the fuzz harness only. On the
  way it records the spans glibc's `get_subexp` would find for each
  back-reference (node, position, length: `RxEntry`, deduplicated by a
  hash trie) and the end nodes reached at each position, and moves them
  to the front of its arena when done. For the start chosen, `rxreach`
  then builds glibc's automaton states from them, path-insensitively
  as glibc does: the closure of what arrives at each position, moving
  on by characters and by the recorded spans, holding only the nodes
  whose context allows them. `rxsift` keeps only nodes of those
  states (glibc's sifting goes through `state_log`), and puts a
  back-reference in a sifted state only through such a span that leads
  into the set where it ends (glibc's `sift_states_bkref`); its empty
  move is no epsilon move (glibc's inverse closures do not go through
  it). When the sifted state at the start is empty, glibc retries with
  the next shorter end its automaton reached before giving up the
  start; when it is not empty but lacks the start node, the walk fails
  and so does the whole search. glibc's `limits` (the local sift that
  pins the group to the span's bounds) are not modelled: the walk
  checks the text, which has been enough for every pattern without
  repetition. A start whose sifting fails gives its spans' memory back.
- The spans and end records cost little where the spans are few
  (`(.*)x\1` on 10000 "ab": 5.0 s, then 5.2 s; `(.*)\1\1x` on 3000
  a's: 0.69 s, then 0.75 s), but they are kept once each per start,
  which costs where a search finds many: with two groups it finds a
  span for most pairs of position and length. -O2 on Windows, before
  then after: `(a*)(a*)\1\2x` on 600 a's and `bx` 10.6 s, 15.0 s;
  `(.*)(.*)\2\1x` on 400 a's and `bx` 1.7 s, 2.1 s; `(a*)(a*)\2\1c`
  on 400 a's 1.7 s, 2.1 s (the review measured 30% more peak memory
  there). Leaving out the records takes the first back to 11.3 s; a
  flat hash set in place of the trie was no faster. The records are
  not bounded by the memo's 256 MiB (notes/issues.md).
- Both back-reference searches memoize (`RxMemo`), which keeps
  `((a|aa)*)\1\1c` and its like polynomial: the walk, the moment after
  a character, its whole state (node, position, registers and previous
  registers); `rxlongest` the node, position, whether a back-reference
  took the character, and only the registers back-references read.
  `rxlongest` wants the union of what its paths reach, so a state seen
  before is dropped. The walk is glibc's first-success backtracking,
  whose path from a state depends on nothing else and never returns to
  it, so a state seen again failed before; it backtracks as that search
  ended, from a dead end or from an end with an unclosed group, which
  succeeds with the registers of then when the fail stack is empty.
  A bit per (node, position) gates the records: a state is looked up
  and recorded only where that pair was reached before, so each state
  is searched at most twice, and a search where nothing repeats (most
  of them, like `(.*)x\1`) pays a bit test after each character, not a
  hash, trie walk and record. The bits are zeroed only once the search
  has consumed as many characters as they take words, so a start that
  fails at once (`x(.)\1` on a long subject) costs nothing more. A
  first version with neither made those searches 2x slower; now they
  are 0-8% slower than without a memo.
- The memo takes chunks of the search's arena (64 KiB, or half of what
  is left), up to 256 MiB and half of what is left at `rxexec`, then
  makes no more records. When the search's own frames (`RxFrame`,
  `RxFail`) find the arena short, the memo is dropped and its chunks
  become frames, so a search runs out of memory only where it would
  have without a memo, give or take chunk headers and chunk ends too
  short for a frame (the smallest arenas six searches fit in grew by
  16 to 136 bytes). The first version kept the memo, and `(b)\1|a*c`
  on 2400 a's in 256 KiB ran out of memory (regex_test checks it). A
  search past its records' room, or one that dropped them, is
  exponential again where the paths are. Arenas never decommit, so a
  big search (`^(a+)+\1$` on 1000 a's: 96 MB) leaves the scratch arena
  that large for the shell's life (notes/issues.md, M8).
- Timings (-O2, Windows), before then after: `((a|aa)*)\1\1c` on 24
  a's 0.06 s, 300 a's (no match) 0.02 s; `(a*)*\1b` 24 a's 4.2 s, 300
  a's 0.8 s; `^(a+)+\1$` 24 a's 2.7 s, 300 a's 0.02 s, 1000 a's 0.42
  s; `((a|aa)*)\1\1` (a match, the walk) 50 a's 0.9 s, 1000 a's 0.002
  s; `(.*)x\1` on 10000 "ab" 4.8 s, 4.9 s. Old and new agree on
  32932 generated back-reference cases (`regex_diff`'s skipped class
  included; subjects up to 34 characters), with big arenas and with
  40 KB and 100 KB ones. A 20-minute `tools/fuzz regex` run on the
  first version (2 cores) saved 18 differences from glibc, every one
  also the old code's; they are listed in notes/issues.md.

### glibc's quirks reproduced

- No REG_NEWLINE, yet `^` matches after a newline the match consumed and
  `$` before one it goes on to consume (`a$.` matches `a\nb`), as the
  automaton's transitions on `\n` use the newline context. Sifting does
  not allow the latter, so with groups and forks such a match is
  rejected and the search goes on (`(a$.|a)` fails on `a\nb`); without
  forks the walk fails and so does the whole match (`(a)$.`).
- An empty match at a start where the automaton then stays in its
  initial state is reported where glibc's skip-ahead stopped:
  `a*\B` on `ca.` gives (2,2) (`rxstall`).
- A start whose match sifting cannot place is abandoned and the search
  goes on from the next position (with back-references, after the
  shorter ends).
- `(^a)+` never matches `aa`, `(\ba)+` matches it whole: anchors in the
  `+`/interval copy filter only themselves.
- glibc's `get_subexp` takes the lowest-numbered close node of a group
  in a state: a back-reference to a group copied by an interval cannot
  see spans closed by a later copy at the same position, so
  `(a?){2}\1` never matches (`copies`, two-pass `rxlongest`). The same
  holds for the copies glibc makes after anchors: in `(a|\b|())\1\|`
  on `c|` the plain close node of the `()` alternative hides the
  copies after `\b`, so the group is `()`'s. Only close nodes the state
  holds count: a copy whose anchor fails here is not one.
- glibc's initial state (`create_initial_state`) takes each
  back-reference in the start's closure whose group has a close node
  there to match empty, set or not, and adds the closure after it
  (`re->init`, `initclose`). So in `(|^())\2` the empty alternative
  reaches the end through an unset `\2`; that end node is glibc's
  `last_node`, sifting cannot reach the start from it, and `set_regs`
  fails, so the whole search fails: `(|^())\2`, `(|\b())\2`,
  `(|y|^(a|))\2` never match (`(y|^(a|))\2` does).
- `get_subexp` checks a span by walking states built from the real
  context of each position (`check_arrival`), where a newline is no
  line boundary without REG_NEWLINE: a span whose way from the group's
  open node to the back-reference passed a `^` after, or a `$` before,
  a newline only the automaton's quirk let through cannot be used
  (`quirk` in `rxlongest`): `.^(a)\1` never matches `\naa`, nor
  `(.)^\1` `\n\n`.
- A back-reference must satisfy the constraints on what follows it
  before its span counts (`transit_state_bkref`): in `(|a)$\1|(a)\2`
  on `aa`, `\1` after `$` cannot take the second `a`.
- Sifting only keeps nodes of the automaton's state at each position:
  the original of a node an anchor copied is not in it, so in
  `$.()\1|` on `\n` the unconstrained `.` cannot sift a way back to
  the start from the longest end; glibc retries the empty end and
  matches (0,0) (`rxreach`; the old rule took any non-empty sifted
  state and the walk then failed the whole search).
- Where a back-reference arrives, empty or not, glibc rebuilds the
  state from the real context (`transit_state_bkref`,
  `merge_state_with_log`), so a newline the match consumed before it
  is no line start: `.()\1^` never matches `\n`, while `.()^` does.
- An initial-state back-reference taken without a span
  (`create_initial_state`) cannot be passed by `get_subexp`'s search
  for later spans, so no group before it can be referred to after it:
  `^|(\B|)(^)\2.(\B|)\1.` matches empty on `ab`. That growth comes
  before the context filters the state, so an end node after it can
  make the state final even where its anchors fail.
- glibc's retry of shorter ends (`prune_impossible_nodes`) takes a
  state as final when it holds an end node at all (`halt`), even one
  whose context fails, and then sifts from node 0, what
  `check_halt_state_context` returns for none: `\>(^|a)\1$|(a|b)$\>.`
  on `a\n  ` matches (0,0) with no groups, and `($).(^)|\'(^)\3|)a`
  reports group 1 open at the match start (`rxendat`, len -2 records).
- With back-references, glibc's search does not skip ahead in its
  initial state (`rxstall` gives nothing).
- In UTF-8, glibc's search skips starts inside a character unless its
  compiler found the pattern simple enough to run byte by byte
  (`optimize_utf8`: no REG_ICASE, no `\b \B \< \>`, no bracket glibc
  makes a COMPLEX_BRACKET, that is with a class, `\w \W \s \S`, a
  range, negation or a multibyte character). Then the inside of a
  character is a byte like any other, where matches may start
  (`$'\xa5'` matches `å` at 1, `$'\xa5x[^a]'` never matches `åxy`;
  `rxstart`, `Regex.midchar`). A byte after an incomplete sequence is
  not inside a character.
- `[[.space.]]` and other named collating symbols are invalid (no
  collation rules in C and C.UTF-8); `[[=ab=]]` likewise; `[[:word:]]`
  and `[[:ascii:]]` are not classes; under REG_ICASE `[Z-a]` is an
  invalid range (`[Z-A]`) and an escaped lowercase letter (`\a`) never
  matches, since glibc upper-cases the pattern but not escapes.

### Known differences (deliberate or not yet done)

- Back-references in patterns with repetition: glibc decides which
  spans a back-reference may use with a path-insensitive search
  (`get_subexp`, `check_arrival`, `sift_states_bkref`,
  `check_dst_limits`) that regex.cpp approximates by an exact path
  search. Nested stars and empty iterations before a back-reference
  (`(a*)*...\1`) then sometimes give other registers or another
  verdict. The harness skips such patterns (back-reference plus
  `* + ? {`); plain ones are compared.
- UTF-8 classes, `\w`, word boundaries and case folding are ASCII-only
  (glibc uses iswctype/towupper): `[[:alpha:]]` does not match é.
- Size: patterns whose tree would pass 2^20 nodes (`(a{100}){100}...`,
  a chain of 20 `+`) are "Memory exhausted" (code 12), where glibc
  allocates on; nesting deeper than 500 groups likewise, for the stack.
- Every `=~` compiles afresh, as in bash; no cache.

### glob.cpp

- Follows bash's `glob_filename`/`glob_vector`: split at the last slash
  (with extglob the last one outside groups, `glob_dirscan`), expand
  the directory part the same way, then match the last component in
  each directory found. A component without glob characters (bash's
  `glob_pattern_p`: a bracket may span slashes, `+(`, `@(` and `!(`
  count even with extglob off) is checked with lstat after a stat of
  its directory, never listed; that finds dangling links and names in
  unreadable directories.
- `**` (globstar): `GX_ALLDIRS` lists every name below the directory,
  entering directories but not links to them (lstat); `GX_ADDCUR` adds
  the directory itself (`a/**` gives `a/`), as a "" placeholder from a
  null directory. A leading run of `**/` and a trailing run collapse
  as bash does; `**/**` is `**`; a link to a directory met by `**/` is
  listed (`link/`) but `**/x` does not look inside it. `**/a/**` lists
  names more than once, as bash does.
- The order before sorting is bash's: each directory's matches in
  reverse listing order, `.` and `..` listed first.
- Each directory is listed at most once per expansion (`GlobDir`,
  keyed by its path as written), and an entry's type comes from the
  listing (`Dirent.type`), so stats happen only for a link, a literal
  component or a trailing slash. Component patterns are compiled once
  per directory (`globprog`, `progmatch`).
- GLOBIGNORE: patterns split at colons outside brackets and extglob
  groups (and quotes and backslashes), as `skip_to_delim` does; command
  substitutions in the value are not skipped. Each pattern matches the
  whole path with PM_PATHNAME (bash's trailing-star quirk included);
  `.` and `..` as the last component always go.
- GLOBSORT (bash 5.3): name (the default), size, mtime, atime, ctime,
  blocks, numeric, nosort; a leading `+` is ignored and `-` reverses;
  nothing after the sign means name; any other value is the default.
  Ties break by name in the same direction; numeric compares all-digit
  names by value (saturating) and puts them first, equal values keeping
  their order (glibc's qsort is a merge sort; ours is stable). A failed
  stat sorts as -1. Names compare by byte (strcoll in C and C.UTF-8).
- nullglob, failglob, dotglob, nocaseglob and globskipdots as before;
  spec 768 covers failglob in groups, functions, comsubs and `for`.
- Redirection words are not split in POSIX mode, nor globbed there
  unless interactive (bash's W_NOGLOB in redir.c); `$(< file)` expands
  its word as a redirection's (it used `expandstring`: no globbing).

### pattern.cpp and expansions

- `patprog`/`progmatch`: a pattern compiled once, byte-wise and wide,
  for matching many strings.
- `patsearch`/`searchnext`: `${x//p/r}` searches one string in one
  pass: the pattern, the string's context and, for a pattern of varying
  length, every match start (one reversed match) are computed once, so
  each search costs what it examines. Patterns where `findspan` probes
  or tests for any match first take `patfind` on each remainder, as
  before. `pattern_test` checks it against `patfind` on every golden
  `/` and `//` case.
- `${x//p/r}` searches again only while text remains (no empty match
  after a match that reaches the end); after an empty match it copies a
  whole character in UTF-8 (one byte when invalid), as bash's
  `COPY_CHAR_P`; nocasematch applies to it (not to `#` and `%`).
- Divergent brackets (whose end depends on the element that matched)
  fork with the rest of the pattern compiled once per place
  (`PatRest`), so up to `PAT_MAXFORKS` (10) of them in one sequence
  match as bash; the limit was 4, with the rest compiled per
  alternative.

### vos and platform

- `Stat` gains `ctime` and `blocks`: from stat on POSIX; on Win32 ctime
  is mtime and blocks come from the size in 4 KiB clusters; the vos
  tracks ctime on creation, writes, chmod and utime, and counts blocks
  as ext4.
- The vos checks search permission on every directory a lookup passes
  and read permission for listings (the owner's bits for the user's
  nodes, the others' bits otherwise), and lists a directory newest

- printf (b_printf.cpp) took working memory from a copy of the arena

### Known differences and decisions

### float.cpp

- `F80` is the x87 format: a 64-bit significand with an explicit
  integer bit, a biased 15-bit exponent, a sign. Only parsing and
  formatting are needed: bash's printf does no arithmetic on its
  arguments.
- `f80parse` is glibc's strtold in the C locale: leading space, a
  sign, `inf`/`infinity`/`nan`/`nan(chars)` in any case, hex floats
  (`0x` with no digit is the `0` alone), decimals with an optional
  exponent that is consumed only with digits. Decimal input keeps up to
  12000 significant digits plus a sticky digit (no binary midpoint has
  more), becomes `num/den` as bignums, is scaled to `den <= num <
  2*den` and divided bit by bit for 64 bits, a half bit and a sticky
  bit. `f80round` rounds half to even, with subnormals shifted first
  and tininess detected after rounding, as x87 glibc does: ERANGE for
  overflow (inf) and for an inexact result that is subnormal or zero.
  Text more than 10^4933 or less than 10^-4952 short-cuts to inf or 0.
- `f80format` prints the exact value: the integer part by repeated
  division by 10^9, the fraction by repeated multiplication by 10^9
  (`F80Gen`), only as many digits as the precision needs plus a sticky
  test of the rest, rounded half to even (`f80digits`). `%f %e %g` and
  capitals, flags `# + space - 0` (`'` groups nothing in C and
  C.UTF-8), inf and nan without zero padding, `-nan` for a negative
  NaN. `%g` keeps glibc's carry quirk: when it planned `%f` with no
  fraction (the exponent one below the precision) and rounding made the
  integer part longer, it prints `%e` with no fraction either (`%#.2g`
  of 99.99 is `1.e+02`).
- `%a` is glibc's ldbl-96 layout: the leading hex digit is the
  significand's top nibble (`1` is `0x8p-3`), subnormals use exponent
  -16385, trailing zeros go, and rounding is half to even on the hex
  digits, an `f` leading digit carrying to `1` with the exponent up 4.
- In printf, a float argument goes through `getfloat` (bash's
  messages: invalid number, octal or hex by the text's start, and
  "Numerical result out of range" for ERANGE, with the value still
  printed); the conversion reserves `f80bound` bytes of output first,
  so its bignums can work in the arena beyond without the output moving
  over them. `%.-5f` echoes `%.0-5Lf` as glibc's printf_unknown does.

### printf, besides floats

- Diagnostics come after the complete lines of output written before
  them (`pfflush`), as bash's line-buffered stdout has written them by
  then; the rest of the output follows when printf returns. With `-v`
  nothing is flushed. Not emulated: glibc also flushes a full 4 KiB
  buffer, so an error after more than 4 KiB without a newline lands
  mid-line in bash.
- `%n` assigns its variable (the callback existed but the shell never
  set it).
- `%(...)T` follows an exported TZ (the shell variable, read when the
  first `%(` is met; a temporary binding counts, an unexported one does
  not), parsed as glibc parses POSIX zone strings: names of 3 or more
  letters or `<...>`; offsets `[+-]hh[:mm[:ss]]` with hours clamped to
  24 (to 167 in rules) and minutes and seconds to 59; a missing offset
  is UTC under that name; an invalid name is UTC with an empty name;
  an empty TZ is "Universal". DST without rules gets glibc's built-in
  default, `M3.2.0,M11.1.0` at 02:00. Rules `Jn`, `n` and `Mm.w.d`
  are computed per UTC year as glibc does, including its quirk that a
  year up to 1970 counts days from 1970-01-01. `%z` and `%Z` use the
  zone.
- A `hexdump` fake (util-linux's `-b` layout only) serves printf6.sub.

### read

- `-n` and `-N` count characters in a UTF-8 locale: a lead byte counts
  and its continuation bytes do not (`charstart`); an invalid byte is a
  character. A read stopping at its count first finishes the character
  it is in.
- Unescaped null bytes are dropped, as bash does; the in-memory fast
  path takes the general loop when the text has one.
- `-p`, `-s`, `-e` and `-i` need a terminal, and the shell has no
  terminal detection yet (`test -t` is always false), so they do
  nothing, which is what bash does for every non-terminal input.

### mapfile and readarray

- Options and messages as bash: `-d` (first byte, empty for NUL), `-n`
  and `-s` (line counts), `-O` (origin; without it the array is
  emptied first), `-t`, `-u` (validated like read's), `-C` and `-c`
  (quantum, default 5000). The target goes through `arraytarget(...,
  1)` (namerefs, including an unset nameref losing its attribute and
  `XXX[0]` being refused), `assignslot` (readonly) and must not be
  associative; a scalar becomes element 0, as bash. Attributes apply
  per element (`declare -i`, `-u`).
- Each line is cut at its first null byte, as bash's C strings are
  (after `-t` removed the delimiter).
- Input (`MfIn`): text in memory is scanned in place; a seekable file
  is read in 64 KiB blocks and seeked back to just past the last line
  taken; any other input is read in blocks when every line is taken.
  With a count or a callback a pipe is read through each delimiter
  exactly: by peeking where the platform can, else a byte at a time.
- A callback runs as bash's evalstring does: `callback INDEX 'LINE'`
  with the line single-quoted, under the name `stdin` (bash's messages
  say `stdin: line N:`), after the input is given back (`mfsync`) and
  before the element is assigned; its status is ignored. Bash crashes
  when the callback unsets the array; we carry on.

### Platform: peeking pipes on Linux

`os_peek` on Linux tees the pipe into a private pipe and drains that
(`tee(2)` with SPLICE_F_NONBLOCK; zero when the pipe holds nothing,
-1 when the handle is not a FIFO), so read and mapfile take a line per
system call on pipes instead of a byte, still consuming nothing past
the delimiter. Other POSIX systems keep -1. Curated checks against bash
on real pipes (partial reads followed by `cat`, `head`, slow writers,
`read -u` on a process substitution) agree.

### Substrings

`${s:off:len}` counted bytes even in UTF-8 (printf6.sub's
`${V:0:2}` cut a character in half). It now counts characters there
(`utf8substring`; invalid bytes are characters of their own),
skipping ASCII 8 bytes at a step and counting the whole value only
when an offset or length is negative.

### What closing changed

- **POSIX mode** follows bash's posix_initialize: `set -o posix` (and
  `--posix`, and `local -` restoring it) binds POSIXLY_CORRECT=y and
  turns on interactive_comments, sourcepath, expand_aliases,
  inherit_errexit and shift_verbose; `set +o posix` unsets
  POSIXLY_CORRECT and resets expand_aliases (to interactive) and
  shift_verbose. Assigning or unsetting POSIXLY_CORRECT switches the
  mode. A temporary binding (`POSIXLY_CORRECT=y cmd`) saves those five
  options once and restores them when it goes. The inherit_errexit
  check for command substitution no longer also tests POSIX mode,
  since the mode now sets the option.
- **Aliases in command substitutions.** The body of `$(...)` and
  `${ ...; }` is printed, then parsed again when it runs. As in bash,
  the first parse expands aliases only in POSIX mode and the second
  only outside it (`runsource(..., comsub)`), until a command in the
  body changes expand_aliases. Backquotes keep the global setting.
- **`${ ...; }`** turns -v off, and -e off without inherit_errexit,
  for its body and restores both afterwards, as `$(...)` does.
- **Aliases:** `findalias` no longer returns unaliased entries (they
  stay in the trie as tombstones for BASH_ALIASES order), which had
  expanded to nothing. `alias` and `BASH_ALIASES[k]=` reject names
  with metacharacters, quotes, `$`, `<`, `>` or `/`.
- **let and associative subscripts:** the text `let` evaluates is
  already expanded, so (compat 52 and later, or array_expand_once) an
  associative array's subscript ends at its first `]` with no quoting
  (`ArithEnv.literalsub`).
- **Indirection:** `${!N}` of an unset positional or special expands
  as unset (`${!9:-x}` gives x); only an unset variable or an element
  of a missing array is "invalid indirect expansion". `${!a[@]}` is
  the keys only when the brace follows; with an operator it is an
  indirection (`${!v[@]@Q}`).
- **@a and @A** report the attributes of a variable without a value
  (`declare -lr v; ${v@A}` gives `declare -rl v`), also for `[@]`.
  Under set -u, a non-empty array's @a and @A are not unbound for want
  of element 0.
- **`${x//p/r}`:** after `//`, a pattern may start with a slash
  (`${a///a/}`): bash looks for the delimiter from the second
  character.
- **`${x@P}`** follows bash's decoding: `\[` and `\]` give \001 and
  \002, and `\n` gives CR LF, when an editing mode is on; `\$` stays
  backslashed when the result will be expanded; `\s` is the base name
  of the shell's argv[0] (`Shell.shellname`); names, directories and
  `\D{}` are made visible (^X) and backslash-quoted for the expansion;
  the time escapes use the printf time code and an exported TZ; `\!`
  and `\#` are 1, and POSIX mode's `!` and `!!` work.
- **test:** `os_isatty` in every platform layer (isatty(3), a Windows
  console, the vos terminal) backs `test -t`. The vos keeps atime as
  relatime does, so `test -N` sees writes since the last read, and its
  standard handles and pipes belong to the user. A `chgrp` fake checks
  its operands.
- **Background jobs and here-documents:** `spawnbg` materializes the
  here-documents a background vproc inherits, so that both read one
  open file (`{ read l; } &` in a loop over a here-document reads
  successive lines). Other vprocs still get a copy (m3a.md,
  Materialization).
- **Coprocesses:** a reaped coprocess whose variable is readonly
  reports `NAME: cannot unset: readonly variable`, as real bash does
  every time (it is not a race). The oracle's vos has /etc/passwd and
  /etc/group.
- **exit in a function** runs the EXIT trap before unwinding the
  function, which it sees in FUNCNAME, its locals and its positional
  parameters. Bash does this for `exit` only; set -e, fatal errors and
  signals unwind first. An unset local keeps only an export it took
  over from a temporary binding (`v=t f`).

### Known differences and decisions

- **Category b is green except for later milestones:** dirstack and
  the ulimit and help parts of redir and vredir are M7, history and
  histexpand M6, and glob-test fails only on its big5 locale part.
- **Inherited descriptors above 2 are invisible.** sh_main imports
  only the standard handles, so `unabashed -c 'echo >&3' 3>&1` reports
  "3: Bad file descriptor", on Linux too (bash writes). redir8.sub
  hits it on the vos. Importing the open descriptors at startup
  belongs to the platform layers (M5a, M5b).
- **redir12 line numbers:** the .right file cites 43, 47 and 52; real
  bash 5.3 cites 44, 48 and 53, the line where the parser finished the
  top-level command (bash's `line_number`, which simple commands do
  not keep but for, case, select and functions save and restore). We
  cite the last simple command's line (41, 46, 51). Fixing it needs a
  separate parser line beside `Shell.line` for the redirections of
  compound commands.
- **let with an unterminated quote in an associative key** (without
  assoc_expand_once): bash reports "bad array subscript" twice and
  "not a valid identifier"; we take the key as `80s`. Spec 823 uses
  assoc_expand_once.
- **POSIX mode** does not model source_searches_cwd, which bash turns
  off in POSIX mode.
