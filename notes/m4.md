### Namerefs (vars.cpp)

- `Value` of a nameref holds the target name in `str` with `V_NAMEREF`.
  `rawlookup` is the binding itself; `lookup`, `getvar` and `getparam`
  follow namerefs.
- `resolveref(sh, name, global)` follows a chain as bash's
  `find_variable_nameref`: at most 8 links ("maximum nameref depth (8)
  exceeded"), a link back to the start or to itself warns "circular
  name reference" and names nothing, except inside a function when the
  variable found is local: then the global binding (`Ref.global`). A
  value `a[sub]` ends the chain with `hassub`. `global` follows only
  global bindings (`declare -g`).
- Assignments use `assignref`, bash's `bind_variable`: when the first
  non-temporary binding of the name is a function's, a nameref there is
  followed scope by scope downward (`bindingat`), each scope as far as
  its own table goes; a loop within one scope exceeds the depth and the
  global variable of the name itself is assigned (this is why
  `typeset -n v=v; v=x` in a function prints both warnings and sets
  the global `v`). Outside functions it is the dynamic chain. A nameref
  without a value takes the assigned value as its target (`declare -n
  r; r=x`), which must be a valid name ("not a valid identifier"
  prefixed by the running builtin, `Shell.bltname`); a readonly one
  fails silently. `anyref` keeps the walk off the fast path: only a
  name with a nameref somewhere in its binding stack pays.
- A target `a[sub]` assigns the element; if `a` is itself a nameref, it
  loses the attribute with bash's warning (global scope only, as bash).
- Arrays: `arraytarget` maps a name to what a nameref names for element
  and list assignments, `read -a`, coprocs and `unset name[sub]`. A list
  given to an empty nameref removes the attribute ("removing nameref
  attribute"); an element of an empty nameref, or a list for a nameref
  to an element, is "not a valid identifier".
- Expansion: `${!ref}` is the last nameref's value; `$ref` for a target
  `arr[@]` expands as `"${arr[@]}"` (getparam returns the list).
- `declare`: `-n` checks self references (an error at global scope, two
  warnings in a function), invalid targets, arrays, readonly targets,
  `ref+=x` self references; without `-n` it acts on the target, in a
  function only through a nameref of the function's own (bash's
  `declare_transform_name`); `+n` follows to the end, assigns there and
  clears the attribute; `-n` on an integer evaluates the name to a
  number and quietly deletes the new variable, as bash.
- `unset` follows (an element target included), `unset -n` touches only
  namerefs; `for` with a nameref variable re-targets it each iteration;
  temporary bindings (`ref=x cmd`) and children's environments bind the
  target (`tempname`); `test -R` looks at the name itself.

### Arrays and associative arrays

- Associative key-value lists (`A=(k v k v)`) expand each word as an
  assignment value: no splitting, no globbing (`$foo` with a space is
  one key, `*` stays `*`).
- `declare name[sub]='(...)'` (quoted) follows bash's rules: an element
  of an existing array, a whole list for `-a`/`-A` or an existing array
  given without a subscript, an element plus the "quoted compound array
  assignment deprecated" warning for a new variable; a literal
  `name[sub]=(...)` is "cannot assign list to array member".
- `${#a[bad]}` reports `[bad]: bad array subscript` and ends the
  command; `${a[bad]}` and `${!a[bad]}` report `a: bad array
  subscript` and go on.
- `${A[@]:=x}` on an associative array assigns key `@`.
- assoc_expand_once/array_expand_once: a builtin's argument (printf -v,
  read, wait -p) keeps its subscript as it is (`SV_RAWKEY`; an indexed
  one is evaluated without expansion, its errors abandoning the command
  and `-c` text like other subscript errors). An unquoted `name[sub]`
  argument (compargs 3, `onewordarg`) of an associative array may hold
  brackets, the key running to the last `]`; declare parses
  `name[key]=` flat, the key ending at the first `]` (`splitrefflat`).
  `let` takes associative keys as they are. `test -v`, `unset` and
  `declare name[sub]=` evaluate indexed subscripts without expansion.
- A subscript may hold a substitution with brackets:
  `a[$(echo ])]=x` (parse.cpp `skipsubscript`).
- In arithmetic, literal brackets of a subscript are not quoted by
  `arithsubscript` (`$(( a[a[0]] ))`), only those an expansion produced.
- A new local's list expands with the caller's variable still visible
  (`local -a arr=("${arr[@]}")`: `SV_NEWLOCAL`, `hidelocal`).

### Dynamic variables and listings

- DIRSTACK (the working directory alone until pushd exists),
  BASH_ALIASES and BASH_CMDS are dynamic: read, they are built as bash
  builds them, the alias and command tables walked in bash's bucket
  order (64 and 256 buckets, FNV-1) into associative arrays of the same
  size, so `${!BASH_ALIASES[@]}` comes out in bash's order (`Alias.seq`
  records definition order for the alias table's chains). Assigning an
  element defines an alias or remembers a path; unsetting one changes
  neither table, as in bash.
- SHELLOPTS and BASHOPTS are readonly dynamic variables (the options on,
  in listing order). Inherited from the environment, they turn their
  options on; exported, children get the current value.
- Full listings (`set`, `declare -p` with no names) show what bash
  shows: dynamic scalars (LINENO, RANDOM, SECONDS, BASHPID, EPOCH*,
  BASH_COMMAND, BASH_SUBSHELL, BASH_ARGV0, HISTCMD, COMP_WORDBREAKS)
  valueless until first read (`Shell.dynread`), then RANDOM and LINENO
  with their last values; GROUPS empty until read; DIRSTACK,
  BASH_ALIASES, BASH_CMDS, BASH_ARGV, BASH_ARGC as `()`; PIPESTATUS
  absent until a command has run. Named (`declare -p LINENO`) they are
  computed, as in bash. LINENO is not an integer; OPTIND is.
  BASH_LOADABLES_PATH has bash's default.
- `readonly` and `export` listings use the `declare -..` form, and in
  POSIX mode `readonly -a name=...`/`export name=...` (only -a and -A
  shown). `local -p name` shows only the function's own locals.
  `readonly name[sub]` is an invalid identifier; `declare +a` and other
  attribute changes on a readonly variable are "readonly variable".
- `declare -f`/`-fp` of a missing function: `-fp` reports "not found".

### Temporary bindings and scope

- `var=x export var` / `readonly` / `declare -x` outside a function: the
  temporary value and attributes reach the binding beneath
  (`belowtemp`: the next binding, which may be a function call's own
  temporary, or a new global). Inside a function, operations on the
  call's temporaries do not propagate.
- A local made while a temporary binding for the declaring builtin
  exists takes its value (`var=value declare -x var` in a function).
- A local declared without a value hides nothing from programs: the
  environment gets the binding beneath.
- `declare -I`/`local -I` inherit the hidden value and attributes.
- localvar_unset: unsetting a caller's local leaves it unset but local.
- `set -k`: assignment words anywhere in a simple command are
  assignments.
- `IGNOREEOF` and `set -o ignoreeof` follow each other, including when
  `local -` restores the options.
- POSIX mode: assignments before a special builtin persist exported.
- `name[sub]=x cmd`: reported as not a valid identifier and skipped;
  the command runs.
- Inherited environment entries that name no variable (`v[0]=x`) are
  passed on to programs (`Shell.badenv`).
- `compgen -A shopt` and `-A setopt` list the option names.

Benchmarks (bench/run, Linux in WSL, against bash 5.3): new `b3`
(indexed arrays; 1.9 s against bash's 191 s at n=1e6, now n=3e5 so bash
finishes) and `b4` (associative arrays, 0.47 s against 1.30 s); b1, b2,
b9 and b10 unchanged by the nameref checks on assignment.

### Decisions

- `DIRSTACK` holds only `$PWD` until pushd/popd/dirs exist (M7).
- Listings show dynamic scalars other than RANDOM and LINENO with their
  current value once read, where bash shows the value from the last
  read.
- `refwarning` and other messages from code without a scratch arena use
  a 1 KiB stack arena with names cut at 256 bytes.
- Assigning through a nameref into a binding of a lower scope that is
  shadowed by a newer one assigns the visible binding (bash would
  assign that scope's own); a full fix needs assignment at a given
  depth.
